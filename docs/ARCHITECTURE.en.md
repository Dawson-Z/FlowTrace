# FlowTrace Technical Architecture & File Reference

> This document was rewritten from the current working tree (macOS 11.0
> deployment target, `xcodebuild test` 206 passing). All type names,
> method names, and SQL table names are drawn from the actual code;
> quoted comments are flagged with their source.

---

## 1. Project scope and hard constraints

FlowTrace is a fork of
[foamzou/ITraffic-monitor-for-mac](https://github.com/foamzou/ITraffic-monitor-for-mac)
(iTraffic). It preserves the upstream's core idea — a small menu-bar
network monitor that drives `/usr/bin/nettop` to display per-process
traffic — and adds a batch of purely user-space features on top.

| Constraint | Value |
|---|---|
| Distribution | Source in this repository plus `.dmg` / `.zip` on GitHub Releases; released binaries are signed with a self-signed identity and **not notarised**, so users must allow the first launch themselves |
| License | MIT, with the upstream `foam` copyright line retained alongside this fork's |
| Bundle ID | `local.FlowTrace` |
| Deployment target | macOS **11.0** |
| Privileges | No sandbox extension, no `NetworkExtension`, empty entitlements `<dict/>` |
| Network calls | **Zero.** The upstream rule "exactly one network request, only when clicked" is hardened in this fork to "no network request under any circumstance" |
| Updates | **No auto-update**, and there will not be one — it follows directly from the row above: a tool that explains every process's traffic should not generate traffic nobody can explain |
| Dependencies | Zero third-party packages; SQLite uses the system `import SQLite3` |
| App form | Menu-bar app (`LSUIElement = true` in `Info.plist`), popover-style UI |

Lower bound because we stay on user-space `nettop`: there is **no** per-domain /
per-connection attribution, and no NetworkExtension-grade per-interface
accounting. This is a deliberate architectural choice.

## 3. Overall architecture

### 3.1 Layered view

```
┌──────────────────────────────────────────────────────────────┐
│  Acquisition (Service + Feature/Interface)                   │
│   NettopRunner (per-process)      InterfaceMonitor (socket)  │
│        │ onFrame                        │ onAggregate        │
├────────┼────────────────────────────────┼────────────────────┤
│  Parse / normalise (Network.swift)        │                    │
│   parser(): the only delta ÷ interval   │                    │
│   handleFrame(): fan-out to consumers    │                    │
├─────────────────────────────────────────┼────────────────────┤
│  In-memory state (SharedStore singletons)  ▼                  │
│   HistoryStore / StatusDataModel / InterfaceModel            │
│   ListViewModel / UsageAggregator / InterfaceMinuteAggregator │
│   ProcessUsageAggregator / QuotaMonitor / ProcessAlertMonitor │
├──────────────────────────────────────────────────────────────┤
│  Persistence (HistoryPersistence, SQLite)                    │
│   history / interface_history / interface_minute /            │
│   process_usage / process_alert                               │
├──────────────────────────────────────────────────────────────┤
│  Presentation                                               │
│   popover: ContentView (+ StatusBarView in menu bar)        │
│   SettingsRootView (standalone NSWindow)                      │
│   HistoryWindowView (standalone NSWindow, 3 tabs)            │
└──────────────────────────────────────────────────────────────┘
       Cross-cutting: Appearance (accent) · Localization · Logging
```

### 3.2 Key design principles

1. **Normalisation happens once.** `nettop` runs in `-d` (delta) mode at `-s interval` cadence, so a frame reports bytes moved over the whole sample window. `Network.parser` is the **only** site that divides by `interval` (the `ProcessEntity.inBytesPerSec` field name carries the unit). Dividing again anywhere downstream reproduces upstream issue #28 (the list renders double the menu-bar rate).
2. **A single container assembles singletons.** Every cross-surface `ObservableObject` lives on `enum SharedStore` (`Store.swift`), wired by `AppDelegate` during launch.
3. **Main-queue fan-out per frame.** Subprocess I/O runs on its own serial queue; frame parsing on the callback thread; but every `@Published` write hops the main queue (`DispatchQueue.main.async` inside `Network.handleFrame`).
4. **Modules are self-contained.** Every `FlowTrace/Feature/<Name>/` brings its own view, model, and pure-function helpers, and is picked up by `project.yml`'s path wildcard automatically.
5. **Degradation must be safe.** When SQLite fails to open, `SharedStore.historyPersistence` is `nil`; affected features fall back to memory-only and log an error, but launch still succeeds.

> Two non-obvious pitfalls inherited from the upstream `NettopRunner`: it must
> wrap nettop in `script` for a pseudo-TTY **and** keep the stdin pipe alive;
> closing stdin makes nettop's TUI loop spin at 100 % CPU.

### 4.3 `FlowTrace/Feature/` — branch-specific modules

#### Appearance (accent-colour subsystem)

| File | Responsibility |
|---|---|
| `AccentColor.swift` | `AccentSource` (`.system` / `.custom`), `AccentColorManager` (single source of truth; UserDefaults keys `ft.accent.source` / `ft.accent.hex`; fresh installs default to `.custom` + `#00CFFF`; watches the system accent via the `AppleColorPreferencesChangedNotification` distributed notification), `AccentHexField`, `\.appAccent` environment value, `View.appAccentScope(_:)` (the one application point per window root — applies `.tint` (12+) / `.accentColor` (11) and publishes the environment value), `animationIdentity` (constant in `.system` mode so an accent revision does not cause a redundant fade) |

#### Localization

| File | Responsibility |
|---|---|
| `LocalizationManager.swift` | `Loc` (`Loc.l(_:table:)` — the only string-lookup entry point across the app; `Loc.appDisplayName`; `Loc.dateFormatter(template:locale:)` for every user-visible date) plus `LocalizationManager.shared`. #### Logging

| File | Responsibility |
|---|---|
| `AppLogger.swift` | `AppLogger`: subsystem `local.FlowTrace` + 7 `Logger` categories. `LogFileSink`: appends to `~/Library/Logs/FlowTrace.log` (enabled by default in Debug builds or via the `ITRAFFICPLUS_FILE_LOG=1` env var); serial queue, append-only |
| `LogHelpers.swift` | `Log.<category>` helpers — the only recommended logging entry point: every line goes through both the `os.Logger` and the file sink |

Why two sinks: on macOS 11+ an ad-hoc-signed app's `os.log` lines are subject to
a privacy filter — visible in Console.app's "Now" pane while the menu bar
is being clicked, but **not** persisted, so `log show` cannot retrieve them
later. The file sink is unaffected by logd's filter and can be `tail -f`'d.

Category names (also the property names on `Log` / `AppLogger`):
`appDelegate`, `network`, `nettopRunner`, `persistence`, `settings`, `interface`, `l10n`.

#### Usage

| File | Responsibility |
|---|---|
| `UsageAggregator.swift` | Period-usage aggregator: `UsageBytes` (in/out/total) + `today/week/month` + `bytes(forPeriod:)`. `tick()` is called from the frame path and is throttled internally (default 2 s). The menu-bar `P` segment and `QuotaMonitor` share this one source |
| `LocalNotification.swift` | **The one place a local notification is actually handed to the system.** `typealias NotificationDelivery` is the injection seam (`QuotaMonitor` / `ProcessAlertMonitor` / `DataRetentionController` each take one); `LocalNotification.deliver` is the production implementation: it reads `getNotificationSettings().authorizationStatus` **before** calling `add`, because `add` returns `error == nil` even when the app is not authorized — measured on this machine — so a caller that trusted the error would record the notification as delivered and never retry. Completion is hopped to the main queue. The same file hosts `NotificationPermissionModel`, an observable of the authorization status (`refresh()` / `request()`) backing the Settings inline warning |
| `QuotaMonitor.swift` | Quota-threshold monitor: subscribes to `aggregator.$today/$week/$month`; threshold set `{80, 100, custom}`; crossing rule `prev < t && current >= t` (extracted into a static pure function `shouldFire(...)` so it can be unit-tested without a live aggregator); dedup key `"<periodStartISO>:<threshold>"` in UserDefaults `quotaFiredKeys`, auto-resets on period rollover. Includes `ByteFormatter`.<br>**Delivery semantics**: the fired key is written only **after** a successful delivery; a refusal backs the threshold off for 15 minutes (in-memory — the retry happens immediately after a restart) so that granting the permission later actually delivers the catch-up notification.<br>**`bootstrap()` must be called at launch**: `SharedStore.quotaMonitor` is a lazily-initialised `static let`; nothing in the launch path used to touch it, which meant its `init` — and with it the subscriptions — never ran, and the quota feature was silently dead. `AppDelegate.applicationDidFinishLaunching` does the touch |
| `ProcessAlertMonitor.swift` | Per-process abnormal-traffic alert: each direction independently requires both "today's cumulative bytes ≥ the absolute MB floor" and "today's cumulative bytes ≥ 7-day daily median × multiplier"; a zero baseline counts as "any traffic is abnormal". **At most one alert per process per direction per local day** — dedup is enforced by the unique index `(day, name_key, direction)` in `process_alert` (survives restart). `decide(...)` is a pure function.<br>**Delivery semantics**: delivers *before* writing the dedup row — doing it the other way round (the original implementation) meant a refused delivery still recorded it as "today's alert", so the user was never told and the process would never be retried. Same 15-minute back-off after a refusal |

**A test run is neither isolated nor read-only — treat that as a known property, not a bug.** The `FlowTraceTests` bundle runs *inside* the app (`TEST_HOST`), so `applicationDidFinishLaunching` executes for real: a run spawns the two `nettop` subprocesses and reads and writes the user's actual `~/Library/Application Support/FlowTrace/history.sqlite3` and `~/Library/Logs/FlowTrace.log`. Any test that goes through `Loc` / `LocalizationManager.shared` also instantiates `SettingsStore.shared`, which reads the real `UserDefaults` domain and may perform the one-time key migration there. Injecting isolated dependencies keeps each test's *assertions* honest; it does not sandbox the host app.

When you need a genuinely clean room for a manual run, launch the built binary with `CFFIXED_USER_HOME=<dir>` — macOS resolves `NSHomeDirectory()` through `getpwuid()`, so the `HOME` variable alone does **not** redirect Application Support or Logs, while `CFFIXED_USER_HOME` does. It redirects file paths only; `UserDefaults` still resolves to the real domain.

## 5. Persistence: `HistoryPersistence`

### 5.1 Location and open flags

- Path: `~/Library/Application Support/FlowTrace/history.sqlite3`
- **One-time directory handling**: on first launch, the `FlowTrace/` subdirectory is created if it doesn't exist.
- Open flags: `SQLITE_OPEN_READWRITE | SQLITE_OPEN_CREATE | SQLITE_OPEN_FULLMUTEX`
- PRAGMAs: `journal_mode = WAL`, `synchronous = NORMAL`
- **WAL sidecars (backup caveat)**: in WAL mode the on-disk database is **three files** — `history.sqlite3` (everything up to the last checkpoint), `history.sqlite3-wal` (committed transactions not yet merged), `history.sqlite3-shm` (the shared-memory index over the WAL). The app **never runs an explicit checkpoint**: the only `sqlite3_close` sits in `HistoryPersistence.deinit`, and the owner `SharedStore.historyPersistence` is `static` storage that lives for the whole process, so that `deinit` never fires; `applicationWillTerminate` does not close the handle either. **`-wal` therefore normally survives quit.**
  **This is not data loss** — SQLite replays the WAL on the next open, and any reader always sees main + WAL. But **a backup, a move, or a handoff must copy all three files**; copying `history.sqlite3` alone loses the most recent data. Do **not** delete the sidecars to "tidy up" — that discards the transactions they hold. Growth is bounded: SQLite checkpoints automatically at 1000 pages (~4 MB).

### 5.2 Schema

| Table | Columns | Indexes |
|---|---|---|
| `history` | `id` PK, `ts` (epoch ms), `in_bps`, `out_bps` | `idx_history_ts(ts)` |
| `interface_history` | `id`, `ts`, `category` TEXT, `in_bps`, `out_bps` | `idx_iface_ts_cat(ts, category)` |
| `interface_minute` | `id`, `minute_bucket` INT, `category` TEXT, `in_bytes`, `out_bytes` | `idx_ifmin_bucket_cat(minute_bucket, category)` |
| `process_usage` | `id`, `minute_bucket` INT, `name` TEXT, `name_key` TEXT, `in_bytes`, `out_bytes` | `idx_pu_minute(minute_bucket)` |
| `process_alert` | `id`, `day` INT, `name`, `name_key`, `direction` TEXT, `today_bytes`, `baseline_bytes`, `multiplier` REAL, `ts` | **UNIQUE** `idx_alert_unique(day, name_key, direction)` |

**Two time bases coexist; do not mix them up.**

- `ts` — epoch milliseconds (frame-level tables `history`, `interface_history`).
- `minute_bucket` — **local minute ordinal**, i.e. `(epochMs + tzOffsetMs) / 60000` (minute-level tables `process_usage`, `interface_minute`). `ProcessUsageAggregator.bucket(of:)`, `InterfaceMinuteAggregator.minuteBucket(_:)`, and `ProcessUsageModel.rangeBuckets` all share this convention — if any one of them drifts, the heatmap and the app-usage tab desync.

### 5.3 Threading model

- A single private serial queue `DispatchQueue(label: "history-persistence", qos: .utility)` owns every `sqlite3_*` call. **The main thread never touches SQLite.**
- Write methods (`append` / `appendInterface` / `appendInterfaceMinute` / `appendProcessUsage` / `appendProcessAlert`) return immediately; the write happens on the queue.
- Read methods default to `queue.async` and dispatch the completion back to the main queue. The only synchronous read is `recent(limit:)` — bounded, indexed, and only called at launch.

### 5.4 Retention and cleanup — three distinct paths

| Trigger | Method | Coverage |
|---|---|---|
| Once at launch | `prune()` (by `retentionSeconds`) | `history`, `interface_history`, `process_usage`, `interface_minute` (**not** `process_alert`) |
| Daily checkpoint (auto mode) | `pruneExpired(cutoffMs:cutoffBucket:)` / `expiredRowCount(...)` | `ts` group: `history`, `interface_history`, `process_alert`; bucket group: `process_usage`, `interface_minute` |
| User-initiated | `clearAllTables(completion:)` (5 tables), `deleteRange(fromMs:toMs:fromBucket:toBucket:)` / `countRange(...)` (4 tables) | see left |

Default retention is 7 days; the actual value comes from
`SettingsStore.historyRetentionDays` (default 30) at launch.

### 5.5 Query API summary

| Method | Source table | Consumer |
|---|---|---|
| `recent(limit:)` (sync) | `history` | `HistoryStore.bootstrap()` |
| `summary(dayStart:completion:)` | `history` | `HistoryStore.refreshSummary()` (per frame, only publishes when the value changes) |
| `historyUsageBytes(fromMs:toMs:completion:)` | `history` | `UsageAggregator` (today / week / month totals) |
| `interfaceMinuteHeatmap(fromMs:toMs:categories:completion:)` | `interface_minute` | `HistoryHeatmapModel.reload()` |
| `interfaceUsageBytes(fromMs:toMs:interval:completion:)` | `interface_history` (rate × interval) | `InterfaceModel.loadTodayBase()` |
| `processUsage(fromBucket:toBucket:completion:)` | `process_usage` | `ProcessUsageModel.reload()`, `ListViewModel.loadTodayBase()` |
| `exportProcessUsage(...)` / `exportInterfaceMinute(...)` | minute tables | the two `exportCSV()` flows |
| `alertRecords(fromMs:limit:completion:)` | `process_alert` | `AlertLogModel.reload()` |
| `todayProcessTotals(fromBucket:completion:)` / `dailyProcessTotals(fromBucket:toBucket:completion:)` | `process_usage` | `ProcessAlertMonitor`'s today-amount and 7-day baseline |
| `appendProcessAlert(_:completion:)` | `process_alert` | `ProcessAlertMonitor` (when the unique index returns `inserted == false`, it means "already alerted today") |
| `static date(fromLocalMinuteBucket:)` | — | Convert a minute ordinal back into a local `Date`; used by exports |

## 7. Engineering conventions & known pitfalls

### 7.1 Build & resources

- `project.yml` is the single source of truth. After editing, run `xcodegen generate` and commit the YAML **only** — the generated `FlowTrace.xcodeproj` is gitignored on purpose.
- Two targets: the app `FlowTrace` (`MACOSX_DEPLOYMENT_TARGET = 11.0`) and the unit-test bundle `FlowTraceTests` (`bundle.unit-test`, `TEST_HOST` pointing at the app).
- `ASSETCATALOG_COMPILER_APPICON_NAME = AppIcon`. **Deliberately not set**: `GLOBAL_ACCENT_COLOR_NAME`. If it pointed at the bundled `AccentColor.colorset` (hard-coded `#00CFFF`), that asset would become the AppKit control accent at launch and override the root's `.tint(nil)` — so the "Follow system" branch could never fall back to the macOS accent.
- Release enables `ENABLE_HARDENED_RUNTIME` (one of Apple's notarisation requirements). `project.yml` keeps signing ad-hoc so a fresh clone builds without a certificate; the release build overrides the identity on its command line — see AGENTS.md § Releases for the full process.

### 7.2 Code conventions

- **Rate fields carry their unit** (`inBytesPerSec` / `totalInBytesPerSec`). Normalisation happens exactly once, in `Network.parser`.
- **`.help(_:)` needs an `#available` guard** (macOS 11+). Don't raise the deployment target for it.
- **SF Symbols use `.font` for scaling, never `.resizable()`**. At menu-bar sizes, prefer a Unicode glyph (`⌕`, `⚙`, `↗`).
- **Every independently-hosted SwiftUI root needs `.appAccentScope`**: popover, `SettingsPane` (each pane is its own `NSHostingController`, so there is no shared parent to tint), history window.
- **`.tint` only covers what SwiftUI draws**. AppKit-drawn semantic colours (`controlAccentColor`, focus ring, text selection, dropdown) cannot be overridden per-app via public API; a custom accent has to go through the hand-built controls in `AccentControls.swift`.
- Hand-built fields must **commit before teardown**: three hooks are `controlTextDidEndEditing`, `NSControl.textDidEndEditingNotification` (with `object: field`), `NSWindow.willCloseNotification` (matched against `field.window`). Tab switching uses `SettingsTabBar.commitPendingEdit()` to resign before flipping `selection.tab`. **Never commit from `dismantleNSView`** — that runs inside `NSHostingView.deinit` → `PlatformViewChild.destroy()`, and writing back through a `@Binding` there trips SwiftUI's exclusivity check and aborts the process with `EXC_CRASH / SIGABRT`.
- **Never give a bridged AppKit control a fixed width.** `Picker(.segmented)` and `Toggle(.switch)` are AppKit views; they don't wrap or truncate like a SwiftUI `Text` — they overdraw whatever sits beside them. Fixed-width columns hosting SwiftUI `Text` are fine (the `Text` wraps), but if wrapping would grow the row, pair `lineLimit(1)` with `minimumScaleFactor` instead.

### 7.3 Combine / SwiftUI pitfalls (`@Published` fires before write)

`@Published`'s `willSet` semantics mean the sink runs *before* the property is written. Patterns hit in this codebase and recorded:

- Sort mode: the sink must use the **event value**; reading the property would lag one click.
- Refresh interval: same; the sink that restarts subprocesses must update `interval` *before* restarting so normalisation always uses the current value.
- Settings window resize: a synchronous `setFrame` inside the sink re-enters AppKit while SwiftUI is mid-update (window resizes, pane doesn't); defer one runloop turn via `DispatchQueue.main.async`.
- Appearance switch: same — defer one turn, otherwise AppKit coalesces the change away ("UI lags one selection").

### 7.4 Data correctness

- **First frame must be dropped**: both `NettopRunner` and `InterfaceMonitor` drop the first frame after spawn (it's cumulative, not a delta).
- **First frame of every new PID must be dropped**: `ProcessUsageAggregator.seenPids`.
- **`InterfaceMonitor` must skip rows with an empty interface column**; otherwise every count doubles.
- **The minute-bucket accumulator must be cleared whether or not the flush wrote** — leaving it turns the next flush into "sum since the beginning" (the "results far too large" bug).
- **Never call `getAppInfo(pid: 0, ...)` for name-aggregated rows**; every row would share the pid-0 cache slot and render the same name.
