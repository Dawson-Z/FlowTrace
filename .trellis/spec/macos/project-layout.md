# Project Layout

## The two trees

| Tree | Role | Contains |
| --- | --- | --- |
| `FlowTraceForMac/` | App main — entry point, popover, menu bar, models, parser, `nettop` subprocess driver. | Inherited from upstream iTraffic; several files are touched by this fork (see AGENTS.md "Active experiments"). |
| `FlowTrace/Feature/<Name>/` | Self-contained feature modules added by this fork. | `Appearance`, `History`, `Interface`, `Localization`, `Logging`, `Search`, `Settings`, `Usage`. |

**`FlowTraceForMac/` is the upstream skeleton.** It carries names
like `AppDelegate.swift`, `ContentView.swift`, `Service/NettopRunner.swift`,
`Model/`. If a file matches that description, it almost certainly
belongs here.

**`FlowTrace/Feature/<Name>/` is the experimental surface.** If you
are adding a feature or component that does not exist upstream, it
belongs here, under a topic name (`Settings`, `History`, `Usage`,
…).

## Tests and resources

- `FlowTraceTests/` — unit test target, sibling of `FlowTrace/`,
  injected dependencies, no UI.
- `*.lproj/` — localized strings, 21 locales, **flat under
  `FlowTraceForMac/`** (the build system rewrites the path; do
  not move them).
- `FlowTraceForMac/Assets.xcassets/` — app icon, `ContentBGColor`,
  `blank.imageset`. Anything that must ship as a *bundled image*
  goes here, not under `Feature/`.

## Target wiring

`project.yml` declares two targets:

```yaml
- path: FlowTraceForMac/         # Application
- path: FlowTrace/                # Application (Feature modules)
- path: FlowTraceTests/            # bundle.unit-test
```

Both `sources:` paths include **everything under them**, recursively.
So:

- Adding `FlowTrace/Feature/Audit/Log.swift` requires **no project
  change** — `xcodegen generate` picks it up.
- Removing a file from disk is enough; XcodeGen will drop it on the
  next regen.

## Import rules

- **Across the two trees, anything can import anything.** There is
  no enforced module split, only a directory convention. `Feature/`
  files freely reference `FlowTraceForMac/Store.swift` (the singleton
  container), and `FlowTraceForMac/ContentView.swift` reads from
  `Feature/Appearance/AccentColorManager.shared`.
- **Feature modules may not import each other** except via the
  `SharedStore` singleton. The four `Usage` / `History` /
  `Interface` modules all need each other's snapshots; they do so
  through `SharedStore`, not through direct `import FeatureX`. This
  keeps modules swappable.
- **Do not import `SwiftUI` into types whose purpose is data.**
  A model is a model; if it conforms to `ObservableObject` it does
  need `Combine`, but it does not need `SwiftUI`.

## AGENTS.md is authoritative

`AGENTS.md` at the repo root carries the **convention rules** (rate
fields carry units, deployment target 11.0, every independently
hosted SwiftUI root needs the accent scope, etc.). When this guide
disagrees with `AGENTS.md`, **`AGENTS.md` wins** — update one of
them to match the other before proceeding.

## Hard rules for layout

- **Tests live in `FlowTraceTests/` only.** Do not add a `Tests/`
  subdirectory under any `Feature/` module.
- **Storiesboard / plist / `.lproj` / entitlements stay under
  `FlowTraceForMac/`.** Even when the strings or images are used by
  `Feature/` modules (e.g. `Feature/Localization/` reads them).
- **Do not create a `Common/` or `Utils/` module.** Cross-feature
  helpers belong either in `SharedStore` or as a static `enum` near
  the call sites that need them. Generic "common" folders in this
  repo have all ended up as dumping grounds.
- **Generated files belong in `.gitignore`.** `FlowTrace.xcodeproj/`
  is generated by `xcodegen generate`. `build/` is generated by
  `xcodebuild`. Do not check either in.
