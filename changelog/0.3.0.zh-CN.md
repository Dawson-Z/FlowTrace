## 概览

0.3.0 是 [ITraffic-monitor-for-mac](https://github.com/foamzou/ITraffic-monitor-for-mac) 的
增强版分支。它继承上游的核心思路 —— 小的、按进程维度的 macOS 菜单栏网络监控器，驱动
`/usr/bin/nettop` —— 并在其上叠加了一批纯用户态的新特性。

| 维度 | 0.3.0 的做法 |
| --- | --- |
| 发布形态 | 源码 + Releases 上的 `.dmg` / `.zip`；自签名、不公证 |
| Bundle ID | `local.FlowTrace` |
| 部署目标 | macOS **11.0** |
| 权限 | 无沙箱扩展、无 `NetworkExtension`、entitlements 为空 `<dict/>` |
| 网络请求 | **零**——上游「点击时发一次 GitHub 更新检查」的规则被强化为「任何情况下都不发请求」 |
| 依赖 | 零第三方包；SQLite 用系统 `import SQLite3` |
| 应用形态 | 菜单栏应用（`LSUIElement = true`） |

> 底层能力边界：因为仍是用户态 `nettop`，**无法**做按域名/连接的归因，
> 也做不到 NetworkExtension 那种精确的每接口归属。这是刻意保留的架构选择。

## 一句话功能清单

| 类别 | 内容 |
| --- | --- |
| **进程列表** | popover 中按名称/PID 过滤（恒定大小写不敏感）、6 种排序模式、同名进程合并、每行实时「今日」列 |
| **历史窗口** | 独立 `NSWindow`，三个 tab：App usage、Heatmap、Alert log；每 tab 可导出 CSV |

| **接口维度** | 第二个独立的 `nettop`（socket 模式）按 Wi-Fi / Wired / Local Direct / Other 四桶划分外部流量；popover 底部堆叠条直观呈现 |
| **菜单栏总量** | 在原本的速率 ↙/↗ 之外，可选显示今日 `D` 与配额周期 `P` 段，宽度自适应 |
| **配额提醒** | 80%/100%/自定义阈值的本地通知，按周期月/周/日分组，去重保证每周期每阈值最多一条 |
| **进程异常告警** | 7 日每日中位数 × 倍数 + 绝对 MB 下限的双条件；按自然日 + 进程 + 方向去重（表唯一索引保证） |
| **设置窗口** | 持久化、清理模式、配额、提醒、外观、强调色、21 种语言；配额、示警与存储（提醒模式）启用时若系统通知权限缺失，pane 内嵌橙色提醒（直达系统设置或当场申请）；存储设置变更立即重查保留期 |
| **强调色** | 自定义色通过手绘控件应用（AppKit 渲染无法通过 `.tint` 覆盖语义色） |
| **本地化** | 21 种语言、运行时切换、locale 感知的日期格式 |

## 关键里程碑

里程碑编号仅作历史编号，**与项目状态无关**；已废弃的条目保留在表中并在「修订说明」里标注。

### m1 — 搜索 + 小曲线图

- 新增 `Feature/Search/ProcessSearchBar.swift` + `SearchFilter.swift`（纯函数）、
  `Feature/History/RingBuffer.swift`（O(1) 追加、不分配）、`HistoryStore.swift`（最近 60 帧）、
  `HistoryView.swift`（`Path` 手绘，不用需 macOS 13 的 Charts）。
- 触及上游：`Network.swift`（每帧推入 store）、`ListViewModel.swift`（合并后过滤）、
  `ContentView.swift`（顶部搜索栏 + 底部曲线）、`Store.swift`（新增单例）。
- 剥离上游：`Service/UpdateChecker.swift`、`UpdateStatusView.swift` —— 本分支没有发布频道可查。

### m2 — 纯重构

- `print` → 分类 `os.Logger` + 逐行 tee 的 `Log` 帮助器。
- `formatBytes` 补上缺失的 **GB** 档（此前 >1 GB/s 会显示 `1024.0 MB/s`）。
- 视图 `@ObservedObject` → `@StateObject`；非视图类型（`AppDelegate`、`Network`）上无意义的
  `@ObservedObject` 去掉。
- 部署目标 **10.15 → 11.0**。

### m2.1 — LogFileSink

- macOS 11+ 对 **ad-hoc 签名**应用的 `os.log` 施加隐私过滤，日志可在 Console.app 看到但**不落盘**。
  故增加文件 sink，把同一行写进 `~/Library/Logs/FlowTrace.log`；Debug 默认开启，或设
  `ITRAFFICPLUS_FILE_LOG=1`。

### m3 — 排序模式

- popover 里的分段 Picker（Total / Down / Up / Name）。
- `ListSortMode` 枚举 + `ListViewModel.sort(items:)` 比较器 + `@Published var sortMode`。

### m3.1 — 单元测试 target

- 新增 `FlowTraceTests`（`bundle.unit-test`，`project.yml` 的 `excludes` 保证测试文件不进 app target）。
- `ListViewModelSortTests` 覆盖 4 个比较器、并列时的名称次序、空/单元素、幂等性。

### m3.2 — 独立校验脚本

- `verify_sort.swift` 13/13 通过。存在的原因是当时 `xcodebuild test` 在作者沙箱里写 `.xcresult`
  被拒。**这些脚本后来全部并入 `FlowTraceTests` 并删除。**

### m4 — SQLite 持久化

- `HistoryPersistence`：`history(id, ts, in_bps, out_bps)` + `ts` 索引；WAL +
  `synchronous=NORMAL`；全部 `sqlite3_*` 调用走私有串行队列，**主线程不碰**句柄。
- `HistoryStore` 增加可选 `persistence`；`bootstrap()` 从磁盘最近 60 行回填环形缓冲；
  `SharedStore.historyStore` 改为 `static var`，供 `AppDelegate` 在启动期换装。
- `HistoryPersistence` 自身默认保留期 7 天，实际值由 `SettingsStore.historyRetentionDays`
  在启动时传入（新装默认 30 天）。

### m5 — 设置面板

- `SettingsStore`（`ObservableObject` over `UserDefaults.standard`，key 集中定义）+
  `SettingsView`；popover 头部齿轮（U+2699）打开一个懒创建、复用的 `NSWindow`
  （部署目标是 11.0，没有 macOS 13 的 `Settings { }` scene）。
- 当时六项偏好：launchAtLogin、defaultSortModeRaw、caseInsensitiveSearch、
  showDownloadInStatusBar、showUploadInStatusBar、historyRetentionDays。
- 每个 `@Published` 用 `$prop.dropFirst()` sink 落盘：跳过 `init` 播种时的那次发射，
  避免把磁盘上已有的值再写回一遍。

### m6 — 设置接入运行时

- `defaultSortModeRaw` → `ListViewModel.sortMode` 初值；`historyRetentionDays` → 保留期；
  `caseInsensitiveSearch` → `SearchFilter`；两个状态栏开关 → `StatusBarView` 只画对应行。

### m7 — 开机自启

- `LaunchAtLoginManager` 两套实现：macOS 13+ 用 `SMAppService.mainApp`；macOS 11–12 往
  `~/Library/LaunchAgents` 写一个 launchd 用户代理（`SMLoginItemSetEnabled` 只能注册 helper
  bundle，`LSSharedFileList` 已废弃且过不了公证）。
- `launchAtLogin` 以**系统实时状态**为权威；注册失败会带重入保护地回滚开关。

### m8 — 历史统计扩展

- `HistoryPersistence.summary(dayStart:completion:)`：两条走索引的聚合（今日峰值、24 小时均值），
  在 db 队列执行、主队列回调。
- `HistoryStore.summary` 每帧刷新，但只在值变化时才发布；popover 增加第二行
  「今日峰值 + 24h 均值」；popover 高度 460 → 480。

### m9 — 接口维度

- 新增 `Feature/Interface/` 模块：`InterfaceClassifier`、`InterfaceMonitor`、`InterfaceModel`、
  `InterfaceSummaryView`。
- **第二个独立 nettop**，socket 模式（`-J bytes_in,bytes_out,interface`，无 `-P`），
  两个来源都保持 `-t external`（用户只关心外部流量，不要 loopback）。
- `InterfaceClassifier` 把接口名映射到四个语义桶：Wi-Fi / Wired / Local Direct（AWDL）/ Other。
  纯函数、可单测。
- popover 底部在进程列表与曲线之间加堆叠占比条 + 每桶字节数；高度 480 → 520。

### m10 — 按接口类型的 top 进程（**已移除**）

- 新增 `InterfaceTopMonitor.swift` / `InterfaceTopModel.swift`，每种接口类型各起一个 nettop
  （`-t wifi` / `-t wired` / `-t awdl`），让每种类型暴露自己的 top 进程；`InterfaceModel`
  增加 `topSnapshots`，popover 增加可折叠的三列 "top processes" 块。当时共 **5 个** nettop 子进程。
- 该模块与对应 UI 后来被整体删除，只保留四桶概览 —— 见「修订说明」。

### m11 — 同名合并 + 可配置刷新

- **同名合并**：`ListViewModel.mergeSameNameProcesses` 把同名（大小写不敏感）的行合并成一行 ——
  速率相加、pid 取最小（行标识跨帧稳定）、名字保留首次拼写。菜单栏总量不受影响（它由 `Network`
  里的原始实体算出）。
- **可配置刷新间隔**：`refreshInterval`（1 / 2 / 5s，默认 2）+ Settings 新增 "Monitoring" 段；
  改间隔时重建并重启所有 nettop，且**先更新 `interval` 再重启**，保证 `parser` 里的归一化用的是当前值。
- 该间隔选项后来被回滚为固定 1s —— 见「修订说明」。

### m12 — 多语言

- `Feature/Localization/LocalizationManager.swift` —— 运行时 locale 解析器。默认跟随系统语言；
  `languageOverride` 经按 locale 定位的 `.lproj` bundle 即时切换；缺 key 回退 Base 英文。
- 当时三张 `Localizable.strings` 表（en / zh-Hans / zh-Hant），在 `project.yml` 里作为资源接入。
  popover、设置窗口与窗口标题的所有用户可见字符串统一走 `Loc.l(_:)`。日志保持英文；
  `InterfaceCategory` 的落库值保持稳定（只做显示翻译）。
- **校验时暴露的 UX 问题**（详见 `.trellis/spec/guides/swift-combine-swiftui-pitfalls.md`）：
  - `@Published` 的 willSet 竞态 —— sink 必须使用**事件携带的**值，重新读属性会静默作用于旧值
    （刷新间隔与排序模式都曾「晚一拍生效」）。
  - 桥接分段 Picker 换语言后不刷新段标签（需 `.id(locale)` 重建），静态窗口上还会晚一个事件
    （用 `@State` 镜像绑定解决）。
  - `Bundle.localizedString` 判断「是否命中」必须用哨兵值 —— `value != key` 对英文永远失败
    （英文的 value 就等于 key）。
- **排序 UX**：选项顺序对齐列表列（Name / Down / Up / Total），加列头与每行 Total（in+out）列；
  切换排序立即重排，不再等下一帧 nettop。

### m13 — 历史窗口：热力图 + 接口历史

- `interface_history(ts, category, in_bps, out_bps)` 表：socket 模式的每类别快照在**写入点唯一一次**
  归一化（delta ÷ interval）后逐帧落盘；保留与清理与总量表共用。
- 独立**历史窗口**（懒缓存 `NSWindow`，680×480，可缩放），从 popover 历史区新增的 ⤢ 入口打开：
  范围预设（Today / 7d / 30d）+ 自定义日期；接口类别勾选；由同一份 cell 数据出两种布局
  （每天一行 / GitHub 风格的每天一列）；悬停显示 ↓/↑ 均速与 ≈流量；图例与提示说明颜色 = 小时均速。
- `verify_history.swift` 15 条断言：归一化、本地时区分桶、跨午夜边界、聚合、类别过滤、空窗口、流量换算。
- 数据从本里程碑起才被记录；此前的行不会出现在接口视图里。

### m14 — App usage 页

- `process_usage(minute_bucket, name, name_key, in_bytes, out_bytes)` 表：进程帧的**分钟级预聚合**
  （原始帧约 130 万行/天，分钟行少 4 个数量级）。
- `ProcessUsageAggregator`：内存中累积归一化速率，跨分钟时 flush
  `bytes = Σ(rate) × interval`；分组键是小写进程名，所以进程退出重启仍累计在同一行，
  同名 helper 也会合并。
- 历史窗口新增 **"App usage" 页**：范围内各进程累计 ↓/↑/合计，可排序，含总计页脚与本地化空状态；
  `GROUP BY name_key` 防止大小写变体拆行。
- `verify_process_usage.swift` 12 条断言（合并、跨分钟 flush、字节核算、零流量跳过、范围过滤、排序）。
- 每进程用量从本里程碑起才被记录。

### m15 — 配额提醒 + 菜单栏总量

- `Feature/Usage/UsageAggregator.swift` —— 共享的周期用量积分器。App usage 页、配额监视与菜单栏
  读同一个源，数字之间不会漂移。
- **配额提醒**：Settings 新增 "Quota" 段 —— 开关（同时申请通知授权）、周期（月/周/日）、限额 GB、
  可选自定义阈值（80% / 100% 恒开）。`QuotaMonitor` 每 (周期, 阈值) 跨越发一次本地通知；
  去重 key 存 UserDefaults，周期滚动后自动重新武装。
- **菜单栏总量**：可选追加今日 `D` 与周期 `P` 紧凑段（in+out 合计），横向单行排布；
  开关变化时重新测量状态项宽度。
- `verify_quota.swift` 14 条断言（阈值集合、跨越判定、首次观测只武装、去重、周期滚动、周期 key）。

### m16 — 上传异常告警

- 当时的 `Feature/Usage/UploadAnomalyMonitor.swift`：进程滚动上传基线（最近 15 个非零帧的中位数，
  连续 3 帧去抖），超倍数且超绝对下限才通知，30 分钟冷却；冷启动（基线样本 < 5）不触发。
- Settings 新增 "Upload alerts" 段（总开关、灵敏度倍数 2–50×、最小速率 MB/s）。
- `AppDelegate` 实现 `UNUserNotificationCenterDelegate`，`willPresent` 返回
  `[.banner, .list, .sound]` —— 否则这个长期处于活跃状态的菜单栏（LSUIElement）应用收不到横幅。
- `verify_upload_anomaly.swift` 12 条断言。
- 该监视器后来被整体重写为 `ProcessAlertMonitor` —— 见「修订说明」。

### m17 — 强调色子系统重写

- `Feature/Appearance/AccentColor.swift` 从零重写为自洽子系统：`AccentColorManager`（单一真相源）、
  `View.appAccentScope(_:)`（每个窗口根的唯一应用点）、`AccentHexField`（带校验的 hex 输入）。
- **两个来源**：*跟随系统*（macOS 控制强调色，通过分布式通知
  `AppleColorPreferencesChangedNotification` 实时跟随 —— 在系统设置里改强调色无需重启即重绘）
  与 *自定义*。新装默认 **自定义 + `#00CFFF`**。
- **全局实时生效**：每个窗口根（popover、设置、历史）都观察管理器并应用 `.appAccentScope`，
  它既给所有控件上色（macOS 12+ 用 `.tint`，11 用 `.accentColor`），又把颜色发布为 `\.appAccent`
  环境值供手绘表面读取（排序下划线、热力图格子与图例、桥接开关），因此没有任何表面会与其它不一致。
- **颜色校验只有一处**：hex 解析/规范化（`#00CFFF` / `00CFFF` / `0cf`，输出大写规范形）、
  一切颜色转换走 sRGB、alpha 一律剥离（选择器不带透明度）、落盘的烂值在加载时回落 `#00CFFF`
  而不是崩掉或渲染成不可见。
- 设置 UI：模式选择、实时色块、原生 `ColorPicker`、hex 字段（非法输入红框回退、合法输入吸附规范形）
  与 Reset 按钮。
- 存储 key `ft.accent.source` / `ft.accent.hex`，与旧的 `accentMode` / `accentRGBA` /
  `accentFollowSystem` 一刀两断（旧 key 启动时删除一次）。

### m18 — 原生设置窗口

- 用平台零件搭出标准偏好窗口：`NSTabViewController`（`.toolbar` 风格）承载 tab、窗格间淡入淡出、
  窗口高度随窗格调整，由 `AppDelegate.showSettingsWindow()` 托管。macOS 13 的 `Settings { }`
  scene 仍不可用（目标是 11.0）。
- **每个控件都是平台控件**：开关是真正的 `Toggle`；`EditableNumberField` 保留原生
  `TextField(value:formatter:)` + `Stepper`；hex 字段用原生带边框文本框（只在被拒时画红环）。
  `.plain`/`.borderless` 与硬编码的 9–15pt 字号换成语义文本样式与统一控件列，跟随用户的文字大小设置。
- 破坏性操作用标准 `.bordered` 按钮，确认步骤是原生 `NSAlert`。
- **途中修掉两个（都是跑真实窗口才发现的）**：
  - 选中含数字字段的窗格时 `EXC_BREAKPOINT` —— 自定义 `NumberFormatter` 子类被 SwiftUI 的
    `TextField` 复制，而 `copy(with:)` 会经 Objective-C 重入 `init()`，绕过 Swift 的存储属性初始化。
    改用原生 formatter，范围钳制移到视图的 `onChange`。
  - 切窗格时窗口标题变成 "Untitled"（`NSTabViewController` 默认会传播选中子视图控制器的标题）。
- **另修**：把单一 `SettingsView` 拆成「每 tab 一个 `NSHostingController`」后，设置窗格丢掉了强调色
  应用点 —— 所有设置控件静默回落到**系统**强调色。各 pane 是独立 SwiftUI 根，故 `SettingsPane`
  现在自己应用 scope。
- 该 tab 控制器后来被手绘 tab bar 取代（见 m22）—— 见「修订说明」。

### m19 — 强调色全面到位

- `.tint` 只覆盖 SwiftUI 绘制的内容。AppKit 绘制的一切读的是由**系统**强调色解出的 app-wide
  语义色，公开 API 无法按应用或按控件覆盖。本机实测：`controlAccentColor` #FFC600、
  `keyboardFocusIndicatorColor` #FFFF1A、`selectedTextBackgroundColor` #8B7A3F、
  `selectedContentBackgroundColor` #D19E00。
- 因此需要强调色的表面在 `Feature/Appearance/AccentControls.swift`（新文件）里手绘：
  - **文本字段** → `AccentTextField`：无边框 `NSTextField`、抑制原生聚焦环、外圈由
    `.accentFieldChrome(isFocused:)` 用强调色绘制，并改写 field editor 的公开
    `selectedTextAttributes` 来给文本选区上色。编辑仍归 AppKit（field editor、输入法、撤销），
    只有环、边框与选区色是我们的。
  - **下拉** → `AccentPicker`：按钮 + popover 列表，悬停与选中都用强调色；按强调色亮度选标签色，
    保证浅色强调色也读得清。
  - **日期 / 时间** → `AccentDateField`（本地化月历，含选中/悬停/今日标记，前进导航上限为「今天」）
    与 `AccentTimeField`（HH:MM:SS，带校验与分钟步进）。`AccentDateField` 位于 `AccentControls.swift`，
    因为历史窗口的三个范围过滤器也复用它。
- **主动接受的代价**：手绘控件放弃了 NSMenu 的键盘导航与滚动、系统焦点环、系统日历弹窗。
  「跟随系统」模式没有这些妥协。
- **试过并回退**：给设置 tab 图标上色。非模板的 `NSToolbarItem.image` 会改变 AppKit 绘制整个 item
  的方式（图标**和**标签），而重新赋 image 会让 AppKit 重建 item 并丢掉 toolbar 的选中项 ——
  表现为窗格被弹回第一个 tab。

### m20 — 设置窗口抛光

- **窗格切换瞬时完成**：两个动画都去掉 —— tab 控制器的 `transitionOptions` 显式置 `[]`
  （AppKit 默认是 `crossfade | allowUserInteraction`，不设仍会淡入淡出），每窗格的窗口 resize

### m21 — 文本选区强调色真正生效

设置字段里的强调色文本选区曾被报告「仍然没变」三次，其中两次被当作验证假象打发。它是真 bug，
而上一条「已确认可用」的结论是错的。

- **根因**：着色写在 `controlTextDidBeginEditing`，而**用户点击进入字段时不会调用该方法**。
  此前所有验证路径（程序化聚焦 + `insertText`，以及 `makeFirstResponder` + `selectText`）要么会调它、
  要么根本没产生编辑会话 —— 于是测试一直绿，真实路径画的却是平台色。
- **修法**：改从 field editor 自己发的通知驱动 —— `NSText.didBeginEditingNotification` 与
  `NSTextView.didChangeSelectionNotification`，配合归属判定
  `(editor.delegate as? NSTextField) === ourField`，并在 `dismantleNSView` 里移除观察者。
  高亮不可能在没有选区变化的情况下出现，所以两者合起来覆盖全部情况。
- **在同一真实点击路径上验证**：`attr=#00CFFF rendered=#01C0ED`（应用强调色）。
- **值得留下的教训**：delegate 回调不是「钩子会跑」的证明。先走用户真实走的那条路，再宣称「已验证」。

### m22 — 设置 tab bar 改为手绘

- AppKit preference-toolbar 的选中态会给选中项的**图标与标签**染上系统强调色，且没有覆盖手段。
  故 tab bar 改为五个 SwiftUI 按钮：任何状态都用 `Color.primary`，选中只表现为中性背景高亮。
- **顺带去掉的三个坑**（每个都已经踩过一次）：子视图控制器的标题改写窗口标题（"Untitled"）、
  item image 必须重赋（会静默丢掉 toolbar 选中项并把窗格弹回第一个 tab）、toolbar 标签换语言需手动刷新。
  `applyPaneSize` 现在由选中变化驱动，而不是 tab 控制器的回调。
- **验证时发现的 bug**：在 `@Published` sink 里同步 `setFrame` 会「窗口变了、窗格没变」——
  sink 先于属性写入运行，同步 `setFrame` 在 SwiftUI 更新途中重入 AppKit。延后一个 runloop
  （`DispatchQueue.main.async`）即可修好。与 willSet 陷阱同族。
- **接受的代价**：窗口没有原生 toolbar chrome；每次切换都重建窗格，故窗格局部的 `@State` 会重置。

## 已知限制

- 应用仍然是**用户态 nettop** —— 不能做按域名/连接的归因，也做不到 NetworkExtension 那种精确的
  每接口归属。FlowTrace 故意保留上游的零权限架构。
- **通知需要用户授权，且授权会随重新构建而失效。** 配额与告警都走本地通知；若在
  「系统设置 → 通知」里找不到 FlowTrace 或未开启，通知会被系统静默丢弃（`add()` 在这种情况下
  同样返回成功，所以代码只能靠先查授权状态来判断）。本分支是 **ad-hoc 签名**，每次构建都是新的签名
  身份，而通知授权是按签名身份记录的，因此重新构建后可能需要重新授权：把设置里的对应开关关掉再打开
  即可触发系统授权对话框。
- **备份数据库时必须连边车文件一起拷。** WAL 模式下磁盘上是三个文件：
  `history.sqlite3`、`history.sqlite3-wal`（已提交但尚未合并的事务）、`history.sqlite3-shm`。
  应用不做显式检查点，所以退出后 `-wal` 通常仍在；只拷 `history.sqlite3` 会丢掉最近的数据。
  反过来，删掉边车文件同样会丢数据。详见 `docs/ARCHITECTURE.md` §5.1。
- `xcodebuild test` 可以直接从命令行跑（2026-09 修掉了两个阻塞点：`project.yml` 顶层 `PRODUCT_NAME`
  让 app 与 test target 撞在同一个 `FlowTrace.swiftmodule` 上，以及 `ListSortMode` 改名后遗留的断言）。
  曾经顶替它的 `scripts/verify_*.swift` 独立脚本已并入 `FlowTraceTests` 并删除。
  **注意该测试目标不是隔离的**：测试宿主就是应用本体，`applicationDidFinishLaunching` 会照常执行，
  因此跑测试会拉起真实的 nettop 进程、读写真实的
  `~/Library/Application Support/FlowTrace/history.sqlite3` 与 `~/Library/Logs/FlowTrace.log`。
  跑之前请自行评估。

## 构建

```bash
brew install xcodegen
xcodegen generate
xcodebuild build -project FlowTrace.xcodeproj -scheme FlowTrace -configuration Debug
```

或打开 `FlowTrace.xcodeproj` 按 ⌘R。产物是 `FlowTrace.app`。
