# 0.3.0

FlowTrace — an enhanced, private research fork of
[ITraffic-monitor-for-mac](https://github.com/foamzou/ITraffic-monitor-for-mac).

> **Private / not shipped.** This fork is a local research project. It is not
> a distributable product: there is no release channel, no notarisation
> pipeline, and the bundle identifier is `local.FlowTrace`. Users should
> install the upstream *iTraffic* for daily use; FlowTrace exists to try
> new product ideas without changing the upstream's zero-dependency,
> user-space-only design.

---

## Amendments (entries below that no longer match the source)

The milestone entries are kept verbatim as a record of what was built at the
time. These are the ones the current tree has since diverged from:

- **Milestone 10 — interface-top nettop runs are gone.** `InterfaceTopMonitor.swift`,
  `InterfaceTopModel.swift` and the popover's "top processes" block were removed
  entirely; only the four-bucket interface overview survives
  (`Feature/Interface/InterfaceSummaryView.swift`). The app therefore runs
  **two** nettop subprocesses again — the per-process run and the socket-mode
  run — not the five that entry describes.
- **Milestone 11 — the configurable refresh interval was reverted.** `refreshInterval`
  is now a fixed `let = 1` and the "Monitoring" picker is gone from Settings
  (see the `refreshInterval` comment in `Feature/Settings/SettingsStore.swift`).
- **Milestone 12 — 21 languages, not 3.** `en` / `zh-Hans` / `zh-Hant` grew to
  21 `.lproj` tables (see the resource list in `project.yml`).
- **Milestone 15 — where `UsageAggregator` reads from.** It reads the per-frame
  `history` table, not `process_usage`, and is throttled to one query per 2 s
  (not 15 s), so the menu bar's period totals track real-time traffic.
- **Milestone 16 — the anomaly monitor was rebuilt.** `UploadAnomalyMonitor.swift`
  no longer exists; it is `Feature/Usage/ProcessAlertMonitor.swift`. The rule
  changed from "median of the last 15 non-zero frames, debounced over 3
  consecutive frames, 30-minute cooldown" to "7-day daily median × multiplier,
  gated by an absolute MB floor", and daily dedup moved into the
  `process_alert` table's unique index `(day, name_key, direction)`.
  `verify_upload_anomaly.swift` was removed with it; the standalone harnesses
  present today are the five `verify_*.swift` files at the repo root.
- **The app-source directory was renamed.** `ITrafficMonitorForMac/` is now
  `FlowTraceForMac/`, and `ITrafficMonitorForMac.entitlements` is now
  `FlowTraceForMac.entitlements` — aligning the directory with a target, product
  and bundle id that were already called FlowTrace. Paths such as
  `ITrafficMonitorForMac/Network.swift` in the milestone entries below therefore
  read as `FlowTraceForMac/Network.swift` today. `.trellis/tasks/archive/` keeps
  the old name on purpose: it is a historical record, not live source.

## Highlights

- **Process search** — filter the list by name or PID, case-insensitive by
  default.
- **Multiple sort modes** — Total / Download / Upload / Name, switchable
  from the popover without re-running the PID merge.
- **Live history sparkline** — the last ~2 minutes of total in/out.
- **Persistent history** — SQLite-backed (system `import SQLite3`, zero new
  dependencies) so a restart no longer clears the chart.
- **History statistics** — today's peak and the 24 h average, both derived
  from the persisted rows.
- **Settings panel** — a macOS-native window with preferences that actually
  take effect: default sort, case-insensitive search, status-bar show/hide
  of upload/download, history retention, and launch at login.
- **Structured logging** — `os.Logger` + a file sink for ad-hoc-signed
  builds, replacing the upstream's debug `print`s.
- **Multi-language UI** — Simplified Chinese / English / Traditional Chinese,
  following the system language with an in-app override that applies
  instantly.

## 0.3.0 (research milestone 9) — Interface dimension overview

- New `Feature/Interface/` module: `InterfaceClassifier`, `InterfaceMonitor`,
  `InterfaceModel`, `InterfaceSummaryView`.
- A **second, independent nettop** runs in socket mode
  (`-d -J bytes_in,bytes_out,interface -t external -c`, no `-P`) so the
  process-level data path is untouched and both sources keep `external`
  (no loopback — the user cares only about external traffic).
- `InterfaceClassifier` maps an interface name to one of four semantic
  buckets: **Wi-Fi / Wired / Local Direct (AWDL) / Other**. Wi-Fi device
  names are discovered at runtime from `networksetup -listallhardwareports`
  (this machine's `en1`), which overrides the generic `en*` rule; `awdl0` /
  `llw0` are Local Direct; everything else (bridge*, dynamic virtual like
  `en13`) is Other. Pure function, unit-testable.
- Popover bottom shows a stacked share bar + per-bucket byte counts between
  the process list and the history sparkline; popover height 480 → 520.

## 0.3.0 (research milestone 11) — Same-name merge + configurable refresh

- **Same-name process merge**: `ListViewModel.mergeSameNameProcesses` collapses
  nettop rows that share a case-insensitive display name (Electron helpers,
  "Trae CN Helper.86108/.86111/.86112") into one row — in/out rates sum, pid
  keeps the smallest, name keeps the first spelling. The menu-bar total is
  unaffected (computed from raw entities in `Network`).
- **Configurable refresh interval**: `SettingsStore.refreshInterval` (1 / 2 /
  5 s, default 2). New "Monitoring" section in Settings. `Network` reads the
  interval from Settings and rebuilds/restarts every nettop subprocess on
  change (`applyRefreshInterval`), updating `interval` *before* restart so the
  rate normalisation in `parser` always uses the current value.

## 0.3.0 (research milestone 14) — App usage tab (per-process usage history)

- `process_usage(minute_bucket, name, name_key, in_bytes, out_bytes)` table —
  per-minute **pre-aggregation** of the process frames (raw frames would be
  ~1.3 M rows/day; minute rows are 4 orders smaller).
- `ProcessUsageAggregator` — accumulates normalised rates in memory; on
  minute rollover flushes `bytes = Σ(rate) × interval` (exact for the
  observed window, interval-change-safe: `applyRefreshInterval` settles the
  in-flight bucket with the *old* interval before switching). Grouping key is
  the lowercased process name, so quits/relaunches accumulate under one row
  and same-name helpers merge.
- **"App usage" tab** in the history window (segmented with the heatmap):
  every process's accumulated ↓/↑/total bytes over Today / 7 d / 30 d /
  custom, sortable by the same four keys as the popover, with a grand-total
  footer and a localised empty state. `GROUP BY name_key` keeps case variants
  from splitting.
- `verify_process_usage.swift` — 12 standalone assertions (merge, rollover,
  byte accounting, interval-change flush, zero-traffic skip, range filter,
  sort modes, bucket stability).
- Per-process usage is recorded from this milestone onward.

## 0.3.0 (research milestone 15) — Quota alerts + menu-bar totals

- `Feature/Usage/UsageAggregator.swift` — the shared period-usage integrator.
  Reads `process_usage` bytes (interval-independent, restart-surviving) for
  today / this week / this month; `tick()` is called from the frame path and
  throttled to one query per 15 s. The App-usage tab, quota monitor and menu
  bar all read the same source, so numbers cannot drift apart.
- **Quota alerts** — Settings gains a "Quota" section: enable toggle (asks
  for notification authorization), period (month/week/day), limit in GB, and
  an optional custom threshold (80 %/100 % are always on). `QuotaMonitor`
  fires one local notification per (period, threshold) crossing — dedup keys
  (`periodStart:threshold` in UserDefaults) re-arm automatically at period
  rollover. Disabling has zero overhead (no subscription).
- **Menu-bar totals** — "Show today total" / "Show month total" append
  compact `D1.2G` / `M8.3G` segments (in+out combined) to the status item,
  in a single horizontal row; the status item width re-measures when the
  segments toggle.
- `verify_quota.swift` — 14 standalone assertions (threshold-set
  construction, crossing detection, first-observation arming, dedup,
  period-rollover re-arm, period start keys).

## 0.3.0 (research milestone 16) — Abnormal upload alerts

- `Feature/Usage/UploadAnomalyMonitor.swift` — per-process rolling upload
  baseline (median of the last 15 non-zero frames, debounced over 3
  consecutive frames). Fires a local notification when a process uploads
  at ≥ `multiplier` × its median AND above an absolute MB/s floor, with a
  30-minute per-process cooldown. Cold-start (< 5 baseline samples) never
  fires.
- Settings gains an "Upload alerts" section: master switch (asks for
  notification authorization), sensitivity multiplier (2–50×) and minimum
  rate (MB/s).
- `AppDelegate` now conforms to `UNUserNotificationCenterDelegate` and
  returns `[.banner, .list, .sound]` from `willPresent`, so alerts visibly
  pop even though this menu-bar (LSUIElement) app is active the vast
  majority of the time.
- `verify_upload_anomaly.swift` — 12 standalone assertions (median,
  spike conditions, cold start, consecutive-count, cooldown re-arm, zero
  resets counter).

## 0.3.0 (research milestone 17) — Accent colour, rewritten

- `Feature/Appearance/AccentColor.swift` rewritten from scratch as a
  self-contained subsystem: `AccentColorManager` (single source of truth),
  `View.appAccentScope(_:)` (one application point per window root), and
  `AccentHexField` (validated hex input).
- **Two sources**: *Follow system* (the macOS control accent, live via the
  `AppleColorPreferencesChangedNotification` distributed notification — a
  System-Settings accent change repaints the app without a relaunch) and
  *Custom* (a colour picked in-app). New installs default to **custom +
  `#00CFFF`**.
- **Global, realtime application**: every window root (popover, settings,
  history) observes the manager and applies `.appAccentScope`, which tints
  all controls (`.tint` on macOS 12+, `.accentColor` on 11) *and* publishes
  the `\.appAccent` environment value consumed by the hand-drawn surfaces —
  sort underlines, heatmap cells, heatmap legend, bridged toggles — so no
  surface can drift from the others. One 0.2 s fade covers mode flips and
  colour drags.
- **Colour validation** lives in exactly one place: hex parse/normalise
  (`#00CFFF` / `00CFFF` / `0cf`, uppercase canonical output), sRGB
  normalisation for every colour conversion, alpha always stripped (the
  picker is opacity-free), and malformed stored values fall back to
  `#00CFFF` at load instead of crashing or rendering invisible.
- Settings UI: mode picker, live swatch, native `ColorPicker`, hex field
  (red-outlined revert on bad input, canonical snap on valid input) and a
  Reset button.
- Storage keys `ft.accent.source` / `ft.accent.hex` (a clean break from the
  earlier `accentMode` / `accentRGBA` / `accentFollowSystem` keys, which are
  deleted once on launch).

## 0.3.0 (research milestone 19) — Accent colour, all the way through

`.tint` only reaches what SwiftUI draws. Everything AppKit draws reads
app-wide semantic colours resolved from the **system** accent, and none of them
can be overridden per app or per control with public API — measured on this
machine: `controlAccentColor` #FFC600, `keyboardFocusIndicatorColor` #FFFF1A,
`selectedTextBackgroundColor` #8B7A3F, `selectedContentBackgroundColor`
#D19E00. So the remaining surfaces were hand-built in
`FlowTrace/Feature/Appearance/AccentControls.swift` (new file):

- **Text fields** → `AccentTextField`: borderless `NSTextField` with the native
  focus ring suppressed, wrapped in a ring painted with the accent
  (`.accentFieldChrome(isFocused:)`), and with the text selection recoloured via
  the field editor (`field.currentEditor()` plus the public
  `selectedTextAttributes`). AppKit keeps owning editing — field editor, IME,
  undo — so only the ring, bezel and selection colour are ours. Used by the hex
  field and every numeric field.
- **Drop-downs** → `AccentPicker`: button + popover list, so hover and
  selection use the accent. It measures itself to size the popover, marks the
  current value, and picks the label colour from the accent's luminance so pale
  accents stay readable. Replaces all six menu pickers.
- **Date / time** → `AccentDateField` (month grid with accent selection, hover
  and today marker, localized, forward navigation capped at "today") and
  `AccentTimeField` (HH:MM:SS with validation and minute stepping), replacing
  `DatePicker` and the `NSDatePicker` wrapper. `AccentDateField` now lives in
  `AccentControls.swift` because **all three** history-window range filters use
  it too (`HistoryWindowView`, `AlertLogView`, `AppUsageView`) — not just the
  settings Storage pane.
- **Accepted trade-off** (chosen deliberately over the previous milestone's
  native-first policy): the hand-built controls give up NSMenu keyboard
  navigation and scrolling, the system focus ring, and the system calendar
  popup. "Follow system" mode has none of these compromises, so it remains the
  mode with fully native behaviour.
- **Tried and reverted: tinting the settings tab icons.** The idea was to leave
  unselected tabs in the label colour and tint only the selected one. Two
  problems showed up in real use, so the toolbar was returned to AppKit's native
  rendering: a non-template `NSToolbarItem.image` changes how AppKit draws the
  whole item (icon *and* label), and re-assigning an item's image makes AppKit
  rebuild it and drop the toolbar's selected item — which visibly snapped the
  pane back to the first tab.
- Verified on macOS 15.7.8: the settings tab bar back to native rendering;
  general pane (self-drawn drop-downs, accent-ringed hex field, accent
  switches); storage pane (accent numeric field, HH:MM:SS check-in time,
  month-grid date fields); and the history window's custom-range row (two
  month-grid date fields, dates rendered in the compact `.short` form so they
  fit the 130 pt field). Still uncovered: states that need a real click —
  open-menu hover/selection, the calendar grid, and the accent-tinted text
  selection — because driving the UI is unavailable in this environment.
- **Found while verifying (pre-existing, not from this change):** the history
  window's segmented range picker and its model can disagree — one run showed
  "最近 30 天" selected while the model was `.custom` and the grid rendered the
  30-day data. Worth a separate look; it is the same bridged-segmented-control
  family as the pitfalls already recorded in `.trellis/spec/guides/`.

## 0.3.0 (research milestone 21) — The text-selection tint actually works now

The accent-coloured text selection in the settings fields had been reported as
"still not changing" three times, twice dismissed as a verification artefact.
It was a real bug, and the previous milestone's "confirmed working" entry was
wrong.

- **Root cause:** the tint was written from
  `controlTextDidBeginEditing`, and **that delegate method is not called when
  the user clicks into the field**. Every path used to verify it until now
  (programmatic focus + `insertText`, and `makeFirstResponder` + `selectText`)
  either did call it or produced no editing session at all — so the tests kept
  passing while the real path painted the platform colour.
  Measured with a click posted through the app's own event queue, which is
  what finally reproduced the report:
  `attr=#5C7654 rendered=#5B7553` (the system-accent-derived olive the
  screenshots showed) instead of the app accent.
- **Fix:** apply the tint from the notifications the field editor posts itself —
  `NSText.didBeginEditingNotification` and
  `NSTextView.didChangeSelectionNotification` — with the ownership test
  `(editor.delegate as? NSTextField) === ourField`, and remove the observers in
  `dismantleNSView`. A highlight cannot appear without a selection change, so
  between them they cover every case.
- **Verified on the same click path:** `attr=#00CFFF rendered=#01C0ED` (app
  accent) and a screenshot showing the selection in blue.
- **Lesson worth keeping:** a delegate callback is not proof that a hook runs.
  Drive the path the user actually takes before believing a "verified" claim —
  the whole detour came from trusting a programmatic trigger.

## 0.3.0 (research milestone 22) — Settings tab bar, drawn instead of native

- **The tab bar is now hand-drawn and the tab controller is gone.** AppKit's
  preference-toolbar selection tints the selected item's **icon and label** with
  the system accent (that is what "System Settings" looks like too), and that
  styling has no override — so the selected tab changed colour, which is not
  wanted. The bar is now five SwiftUI buttons that keep `Color.primary` in every
  state and express selection purely as a neutral background highlight.
- **What dropping `NSTabViewController` also removed**, all of which had already
  bitten once: the child view-controller title rewriting the window title
  ("Untitled"), tab item images having to be re-assigned (which silently dropped
  the toolbar's selected item and flipped the pane back to the first tab), and
  toolbar labels needing a manual refresh on a language change. `applyPaneSize`
  now runs on selection change instead of on a tab-controller callback.
- **Bug found while verifying it:** resizing the window synchronously from the
  `@Published` sink resized the window but left the pane unchanged — the sink
  runs *before* the property is written, so the synchronous `setFrame` re-enters
  AppKit while SwiftUI is mid-update. Deferring the resize one runloop turn
  (`DispatchQueue.main.async`) fixes it. Same family as the willSet pitfall in
  `.trellis/spec/guides/swift-combine-swiftui-pitfalls.md`.
- **Accepted trade-off:** the window has no native toolbar chrome, and a pane is
  rebuilt on each switch, so a pane's local `@State` resets (the Storage pane's
  clear-range dates, for instance).
- Verified on macOS 15.7.8: the tab bar renders with a neutral selected
  highlight and label-coloured icons/text, switching to Storage redraws the pane
  and resizes the window to 484 pt.

## Known limitations

- Launch-at-login on macOS 11–12 is reported unsupported; the toggle is inert
  there (it needs a stable signing identity, which this ad-hoc-signed fork
  does not have).
- The app is still **user-space nettop** — it cannot see per-connection
  domains or do per-interface attribution the way a NetworkExtension-based
  commercial product could. FlowTrace intentionally stays on the same
  zero-permission architecture as upstream.
- `xcodebuild test` now runs from the command line. Two blockers were fixed in
  2026-09: a top-level `PRODUCT_NAME` in `project.yml` that made the app and
  test targets collide on one `FlowTrace.swiftmodule`, and test assertions left
  behind by the `ListSortMode` rename. The standalone `scripts/verify_*.swift`
  harnesses that stood in for it have been folded into `FlowTraceTests` (13 → 46
  test methods) and deleted.
