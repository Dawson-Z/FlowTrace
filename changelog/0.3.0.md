# 0.3.0

iTrafficPlus — an enhanced, private research fork of
[ITraffic-monitor-for-mac](https://github.com/foamzou/ITraffic-monitor-for-mac).

> **Private / not shipped.** This fork is a local research project. It is not
> a distributable product: there is no release channel, no notarisation
> pipeline, and the bundle identifier is `local.iTrafficPlus`. Users should
> install the upstream *iTraffic* for daily use; iTrafficPlus exists to try
> new product ideas without changing the upstream's zero-dependency,
> user-space-only design.

---

## Highlights

- **Process search** — filter the list by name or PID, case-insensitive by
  default.
- **Multiple sort modes** — Total / Download / Upload / Name, switchable
  from the popover without re-running the PID merge.
- **Live history sparkline** — the last ~2 minutes of total in/out.
- **Persistent history** — SQLite-backed (system `import SQLite3`, zero new
  dependencies) so a restart no longer clears the chart.
- **History statistics** — today's peak and the 24 h average, both derived
  from the persisted rows.
- **Settings panel** — a macOS-native window with preferences that actually
  take effect: default sort, case-insensitive search, status-bar show/hide
  of upload/download, history retention, and launch at login.
- **Structured logging** — `os.Logger` + a file sink for ad-hoc-signed
  builds, replacing the upstream's debug `print`s.

## 0.3.0 (research milestone 1) — Search + sparkline

### Added
- `iTrafficPlus/Feature/Search/ProcessSearchBar.swift` + `SearchFilter.swift`
  (pure function) — TextField filter at the top of the popover.
- `iTrafficPlus/Feature/History/RingBuffer.swift` — O(1) append, fixed
  capacity.
- `iTrafficPlus/Feature/History/HistoryStore.swift` — holds the last 60
  frames of total in/out.
- `iTrafficPlus/Feature/History/HistoryView.swift` — sparkline drawn with
  `Path` (no macOS 13 Charts framework; deployment target is 11.0).

### Touched (upstream files)
- `ITrafficMonitorForMac/Network.swift` — pushes each frame into
  `SharedStore.historyStore`.
- `ITrafficMonitorForMac/Model/ListViewModel.swift` — applies the search
  filter after the existing merge.
- `ITrafficMonitorForMac/ContentView.swift` — hosts the search bar (top) and
  history view (bottom).
- `ITrafficMonitorForMac/Store.swift` — owns the new `historyStore` singleton.

### Stripped from upstream
- `Service/UpdateChecker.swift`, `UpdateStatusView.swift` — no release
  channel to check; the popover no longer renders a clickable version line.

## 0.3.0 (research milestone 2) — Refactor only

- Replaced `print` with `os.Logger` (categorised: appDelegate / network /
  nettopRunner), plus a `Log` helper that tees every line.
- `formatBytes` gained the missing **GB** tier (previously >1 GB/s rendered
  as `1024.0 MB/s`).
- `@ObservedObject` → `@StateObject` in views; removed the misleading
  `@ObservedObject` on non-View types (AppDelegate / Network), which has no
  subscription semantics.
- Deployment target **10.15 → 11.0**.

## 0.3.0 (research milestone 2.1) — LogFileSink

- On macOS 11+, an ad-hoc-signed app's `os.log` lines do not persist to the
  log store (Apple behaviour), so `Console.app` shows nothing. Added a file
  sink that writes the same line to `~/Library/Logs/iTrafficPlus.log`,
  enabled by default in Debug or via `ITRAFFICPLUS_FILE_LOG=1`.

## 0.3.0 (research milestone 4) — SQLite history persistence

- `iTrafficPlus/Feature/History/HistoryPersistence.swift` — one table
  `history(id, ts, in_bps, out_bps)`, indexed on `ts`; WAL + NORMAL
  synchronous; 7-day retention; all writes serialised on a private utility
  queue (main thread never touches `sqlite3_*`).
- `HistoryStore` gained an optional `persistence`; `bootstrap()` seeds the
  ring buffer from the last 60 rows on disk.
- `SharedStore.historyStore` is now `static var` so `AppDelegate` can swap in
  the SQLite-backed instance during launch (the popover is not shown until
  after launch, so the race that would make `let` necessary does not exist).
- Verified by running the binary: db appears at
  `~/Library/Application Support/iTrafficPlus/history.sqlite3`, rows accrue
  at 1 per frame, and a restart logs
  `bootstrap: seeded 60 frames from on-disk history`.

## 0.3.0 (research milestone 5) — Settings panel

- `Feature/Settings/SettingsStore.swift` (ObservableObject over
  `UserDefaults.standard`, keys centralised) + `SettingsView.swift`.
- Cog glyph (U+2699) in the popover header opens a lazily-created, reused
  `NSWindow` (no macOS 13 `Settings { }` scene — deployment target is 11.0).
- Six preferences: launchAtLogin, defaultSortModeRaw, caseInsensitiveSearch,
  showDownloadInStatusBar, showUploadInStatusBar, historyRetentionDays.
- Each `@Published` has a `$prop.dropFirst()` sink to default; the first
  emission is skipped so `init`'s seed does not write back to disk.

## 0.3.0 (research milestone 6) — Wire settings into runtime

- `defaultSortModeRaw` → `ListViewModel.sortMode` at init (invalid/absent
  falls back to `.total`).
- `historyRetentionDays` → `HistoryPersistence` retention; the launch log now
  reports the resolved value (`retention=14d` observed).
- `caseInsensitiveSearch` → `SearchFilter.filter(caseInsensitive:)`,
  applied on the next keystroke.
- `showDownloadInStatusBar` / `showUploadInStatusBar` → `StatusBarView` only
  draws the corresponding row.

## 0.3.0 (research milestone 7) — Launch at login

- `Feature/Settings/LaunchAtLoginManager.swift` — uses `SMAppService`
  (macOS 13+); on macOS 11–12 it reports `.unsupported` (the old
  `SMLoginItemSetEnabled` only registers a helper bundle and
  `LSSharedFileList` is deprecated and does not survive notarisation).
- `launchAtLogin` is seeded from the *live* OS status, and its sink calls the
  manager rather than writing a defaults key; a failed registration rolls the
  toggle back with a reentrancy guard.

## 0.3.0 (research milestone 8) — History visualisation expansion

- `HistoryPersistence.summary(dayStart:completion:)` — two indexed SQL
  aggregates (today's peak, 24 h mean) run on the db queue, delivered on the
  main queue.
- `HistoryStore.summary` `@Published`, refreshed once per frame but only
  republished when the value changes.
- `HistoryView` second label row: `today peak` + `24 h avg`.
- Popover height 460 → 480 to fit the extra row.

## 0.3.0 (research milestone 9) — Interface dimension overview

- New `Feature/Interface/` module: `InterfaceClassifier`, `InterfaceMonitor`,
  `InterfaceModel`, `InterfaceSummaryView`.
- A **second, independent nettop** runs in socket mode
  (`-d -J bytes_in,bytes_out,interface -t external -c`, no `-P`) so the
  process-level data path is untouched and both sources keep `external`
  (no loopback — the user cares only about external traffic).
- `InterfaceClassifier` maps an interface name to one of four semantic
  buckets: **Wi-Fi / Wired / Local Direct (AWDL) / Other**. Wi-Fi device
  names are discovered at runtime from `networksetup -listallhardwareports`
  (this machine's `en1`), which overrides the generic `en*` rule; `awdl0` /
  `llw0` are Local Direct; everything else (bridge*, dynamic virtual like
  `en13`) is Other. Pure function, unit-testable.
- Popover bottom shows a stacked share bar + per-bucket byte counts between
  the process list and the history sparkline; popover height 480 → 520.

## What did NOT change (deliberate)

- **`NettopRunner.swift`** — kept verbatim, including the `script -q /dev/null`
  TTY wrap and the retained stdin pipe (the "never busy-poll" fix).
- **`Utils.swift`** — `getAppInfo` cache continues to back per-row icon
  resolution.
- The 2-second sample / delta mode / first-frame-dropped rule, with rate
  normalisation still happening exactly once in `Network.parser`.
- The upstream's "no third-party dependencies" rule — kept: SQLite3 is the
  system library, not a package.
- The "no network request" rule, hardened to "no network request period" in
  this fork (the upstream checks for updates only on click; this fork checks
  for nothing).
- **No sandbox / no entitlements expansion** — the entitlements file is still
  the upstream's empty dict.

## Known limitations

- Launch-at-login on macOS 11–12 is reported unsupported; the toggle is inert
  there (it needs a stable signing identity, which this ad-hoc-signed fork
  does not have).
- The app is still **user-space nettop** — it cannot see per-connection
  domains or do per-interface attribution the way a NetworkExtension-based
  commercial product could. iTrafficPlus intentionally stays on the same
  zero-permission architecture as upstream.
- `xcodebuild test` runs in Xcode (⌘U) but is blocked in this development
  sandbox; `verify_sort.swift` covers the comparator instead.
