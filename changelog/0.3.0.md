## Overview

0.3.0 is the enhanced fork of
[ITraffic-monitor-for-mac](https://github.com/foamzou/ITraffic-monitor-for-mac).
It keeps the upstream's core idea — a small, per-process macOS menu-bar network
monitor driving `/usr/bin/nettop` — and layers a set of pure user-space features
on top.

| Dimension | What 0.3.0 does |
| --- | --- |
| Distribution | Source, plus `.dmg` / `.zip` on Releases; self-signed, not notarised |
| Bundle ID | `local.FlowTrace` |
| Deployment target | macOS **11.0** |
| Permissions | No sandbox extension, no `NetworkExtension`, entitlements are an empty `<dict/>` |
| Network requests | **Zero** — the upstream's "one GitHub update check on click" is hardened to "no request under any circumstance" |
| Dependencies | Zero third-party packages; SQLite via the system `import SQLite3` |
| App form | Menu-bar app (`LSUIElement = true`) |

> Capability ceiling: because this is still user-space `nettop`, the app
> **cannot** attribute traffic by domain or connection, nor do the exact
> per-interface attribution a NetworkExtension product can. That is a deliberate
> architectural choice, kept from upstream.

## Feature list in one table

| Area | What it does |
| --- | --- |
| **Process list** | Filter by name or PID in the popover (always case-insensitive), 6 sort modes, same-name merge, live per-row "today" column |
| **History window** | A separate `NSWindow` with three tabs: App usage, Heatmap, Alert log; CSV export on each |
| **History persistence** | SQLite on disk (WAL + `synchronous=NORMAL`), so the sparkline survives a restart; configurable retention, 30 days by default |
| **Interface dimension** | A second, independent `nettop` (socket mode) bucketing external traffic into Wi-Fi / Wired / Local Direct / Other; a stacked bar at the bottom of the popover |
| **Menu-bar totals** | Beyond the original ↙/↗ rates, optional today `D` and quota-period `P` segments, width re-measured on toggle |
| **Quota alerts** | Local notifications at 80% / 100% / a custom threshold, grouped by month / week / day period, deduplicated to at most one per threshold per period |
| **Process traffic alerts** | Two conditions — 7-day daily median × multiplier **and** an absolute MB floor; dedup by local day + process + direction (enforced by the table's unique index) |
| **Settings window** | Retention, cleanup mode, quota, alerts, appearance, accent colour, 21 languages; the Quota, Alerts and Storage (reminder-mode) panes show an inline orange warning when the system notification permission is missing (opening System Settings or asking on the spot); editing any storage setting re-checks retention immediately |
| **Accent colour** | A custom colour reaches hand-built controls (AppKit-drawn semantic colours cannot be overridden through `.tint`) |
| **Localization** | 21 languages, runtime switching, locale-aware date formatting |

## Amendments (earlier entries that no longer match the source)

The milestone entries record what was built at the time. This section lists the
places the current tree has since diverged from. **Read it together with the
milestones below.**

| Milestone(s) | What it said | Current truth |
| --- | --- | --- |
| m5 / m6 | Six preferences, including `caseInsensitiveSearch` | That setting is **gone**: search is always case-insensitive and there is nothing to configure (see `Feature/Search/SearchFilter.swift`) |
| m9 | The hardware-port table won, and both `bridge*` and dynamic virtual interfaces (`en13`) landed in Other | Precedence is now **① name heuristics first** (`awdl0`/`llw0`→Local Direct; `bridge*`→Other), **② the hardware-port table** (port containing `wifi`/`wi-fi`→Wi-Fi, `usb`/`ethernet`/`thunderbolt`→Wired), **③ numeric `en*` not in the table→Wired**. Three things in the original were broken: `== "wifi"` never matched (the real port name is `Wi-Fi`, which lowercases to `wi-fi`, so this machine's `en1` was bucketed as Other); `dropFirst()` should have been `dropFirst(2)` (so dynamic interfaces such as `en13` fell to Other); and `bridge0` never reached the bridge branch because its port name `Thunderbolt Bridge` matched `thunderbolt` first |
| m10 | One nettop per interface type, **five** subprocesses total | The module was **removed** entirely (`InterfaceTopMonitor.swift`, `InterfaceTopModel.swift` and the popover's "top processes" block); only the four-bucket overview remains. The app runs **two** nettop subprocesses again: per-process and socket mode |
| m11 | A configurable refresh interval (1/2/5 s) | **Reverted** to a fixed `let = 1`; the "Monitoring" section is gone from Settings |
| m12 | Three languages (en / zh-Hans / zh-Hant) | Grew to **21** `.lproj` tables (see the resource list in `project.yml`) |
| m13 | The heatmap read `interface_history`, aggregated with `AVG(rate)`, via `historyHeatmap` / `interfaceHeatmap` | It now reads the **`interface_minute`** table, which stores bytes (`interfaceMinuteHeatmap`) — the same minute-cadence source as the App-usage page. Consequence: the heatmap can only show data from the milestone that introduced minute buckets onward; older rows render as empty cells. The window's minimum size is 680×560 |
| m15 | `UsageAggregator` read `process_usage`, throttled to 15 s; the menu bar had "today / this month" `D`/`M` segments | It reads the per-frame **`history`** table (so the menu-bar period totals are real-time, at the cost of running up to one minute ahead of the App-usage tab) and is throttled to **2 s**; the `M` segment was renamed to the quota-period `P` segment (`showMonthInMenuBar` → `showPeriodInMenuBar`, migrated once at launch) |
| m16 | `UploadAnomalyMonitor` (median of the last 15 non-zero frames, debounced over 3 frames, 30-minute cooldown) | **Rebuilt** as `Feature/Usage/ProcessAlertMonitor.swift`: the rule is now "today's cumulative bytes reach the absolute MB floor" **and** "exceed that process's 7-day daily median by the multiplier", and dedup moved into the `process_alert` table's unique index `(day, name_key, direction)` (which survives restarts for free). **At most one alert per process per direction per local day** |
| m18 | The settings window was hosted by an `NSTabViewController` (`.toolbar` style) | That tab controller was replaced by a **hand-drawn tab bar** (see m22); `SettingsView.swift` has also been split into one file per pane (`Settings*Pane.swift`) |
| m3.2 and m13–m16 | Each shipped a standalone `verify_*.swift` harness | Those harnesses were **folded into `FlowTraceTests` and deleted**; there are no `verify_*.swift` files at the repo root any more. The test target is now **205** cases and runs with `xcodebuild test` |
| Throughout | Paths written as `ITrafficMonitorForMac/…` | The directory was renamed to `FlowTraceForMac/` (and the entitlements file with it). Read those paths in the older milestones accordingly; `.trellis/tasks/archive/` keeps the old name on purpose — it is a historical record |
| m15 / m16 | "Crossing a threshold fires a local notification" | Delivery semantics were fixed in 2026-09: `UNUserNotificationCenter.add` **also returns `error == nil` when the app is not authorized**, so delivery now checks `authorizationStatus` first. Quota records a fired key only after a successful delivery, and the alert monitor delivers *before* writing its dedup row; both back off for 15 minutes after a refusal. `QuotaMonitor` also needs `bootstrap()` at launch — it is a lazily-initialised `static let`, nothing in the launch path used to touch it, and the quota feature therefore **never actually ran** |

## Milestones

The milestone numbers are historical labels only and **say nothing about the
project's state**. Superseded entries are kept in the table and flagged in
"Amendments" above.

### m1 — Search + sparkline

- Added `Feature/Search/ProcessSearchBar.swift` + `SearchFilter.swift` (pure
  function), `Feature/History/RingBuffer.swift` (O(1) append, no allocation),
  `HistoryStore.swift` (last 60 frames), and `HistoryView.swift` (drawn with
  `Path` — no macOS 13 Charts framework, the target is 11.0).
- Touched upstream: `Network.swift` (pushes each frame into the store),
  `ListViewModel.swift` (filters after the merge), `ContentView.swift` (search
  bar on top, sparkline at the bottom), `Store.swift` (new singleton).
- Stripped from upstream: `Service/UpdateChecker.swift`, `UpdateStatusView.swift`
  — this fork has no release channel to check.

### m2 — Refactor only

- `print` → categorised `os.Logger`, plus a `Log` helper that tees every line.
- `formatBytes` gained the missing **GB** tier (previously anything above 1 GB/s
  rendered as `1024.0 MB/s`).
- `@ObservedObject` → `@StateObject` in views; the misleading `@ObservedObject`
  on non-View types (`AppDelegate`, `Network`) was dropped — it has no
  subscription semantics without a `body`.
- Deployment target **10.15 → 11.0**.

### m2.1 — LogFileSink

- On macOS 11+, an **ad-hoc-signed** app's `os.log` lines are subject to a
  privacy filter: they are visible in Console.app but **do not persist**. Added
  a file sink writing the same line to `~/Library/Logs/FlowTrace.log`, on by
  default in Debug or via `ITRAFFICPLUS_FILE_LOG=1`.

### m3 — Sort modes

- A segmented Picker in the popover (Total / Down / Up / Name).
- `ListSortMode` enum + `ListViewModel.sort(items:)` comparator +
  `@Published var sortMode`.

### m3.1 — Unit test target

- Added the `FlowTraceTests` `bundle.unit-test` target (`project.yml`'s
  `excludes` keeps the test files out of the app target).
- `ListViewModelSortTests` covers the four comparators, the name tie-breaker,
  empty / single element, and idempotence.

### m3.2 — Standalone verification

- `verify_sort.swift`, 13/13 passing. It existed because `xcodebuild test` could
  not run inside the author's sandbox (the test runner's `.xcresult` write was
  denied). **These harnesses were later folded into `FlowTraceTests` and
  deleted.**

### m4 — SQLite history persistence

- `HistoryPersistence`: one table `history(id, ts, in_bps, out_bps)` indexed on
  `ts`; WAL + `synchronous=NORMAL`; every `sqlite3_*` call runs on a private
  serial queue, and **the main thread never touches the handle**.
- `HistoryStore` gained an optional `persistence`; `bootstrap()` seeds the ring
  buffer from the last 60 rows on disk; `SharedStore.historyStore` became
  `static var` so `AppDelegate` can swap in the SQLite-backed instance during
  launch.
- `HistoryPersistence` itself defaults to a 7-day retention; the value actually
  in force is supplied at launch from `SettingsStore.historyRetentionDays`
  (30 days on a new install).

### m5 — Settings panel

- `SettingsStore` (`ObservableObject` over `UserDefaults.standard`, keys
  centralised) + `SettingsView`; a cog glyph (U+2699) in the popover header
  opens a lazily-created, reused `NSWindow` (no macOS 13 `Settings { }` scene —
  the deployment target is 11.0).
- Six preferences at the time: launchAtLogin, defaultSortModeRaw,
  caseInsensitiveSearch, showDownloadInStatusBar, showUploadInStatusBar,
  historyRetentionDays.
- Each `@Published` persists through a `$prop.dropFirst()` sink: skipping the
  first emission avoids writing `init`'s seeded value back to disk.

### m6 — Wire settings into runtime

- `defaultSortModeRaw` → the initial `ListViewModel.sortMode`;
  `historyRetentionDays` → retention; `caseInsensitiveSearch` → `SearchFilter`;
  the two status-bar switches → `StatusBarView` only draws the matching row.

### m7 — Launch at login

- `LaunchAtLoginManager` has two implementations: macOS 13+ uses
  `SMAppService.mainApp`; macOS 11–12 writes a launchd user agent into
  `~/Library/LaunchAgents` (`SMLoginItemSetEnabled` only registers a helper
  bundle, and `LSSharedFileList` is deprecated and does not survive
  notarisation).
- `launchAtLogin` is seeded from the **live OS status**; a failed registration
  rolls the toggle back behind a reentrancy guard.

### m8 — History visualisation expansion

- `HistoryPersistence.summary(dayStart:completion:)` — two indexed aggregates
  (today's peak, 24 h mean) run on the db queue and are delivered on the main
  queue.
- `HistoryStore.summary` refreshes once per frame but only republishes when the
  value changes; the popover gained a second label row ("today peak + 24 h avg");
  popover height 460 → 480.

### m9 — Interface dimension overview

- New `Feature/Interface/` module: `InterfaceClassifier`, `InterfaceMonitor`,
  `InterfaceModel`, `InterfaceSummaryView`.
- A **second, independent nettop** in socket mode
  (`-J bytes_in,bytes_out,interface`, no `-P`); both sources keep
  `-t external` — the user cares only about external traffic, not loopback.
- `InterfaceClassifier` maps an interface name to one of four semantic buckets:
  Wi-Fi / Wired / Local Direct (AWDL) / Other. Pure function, unit-testable.
- The bottom of the popover gained a stacked share bar and per-bucket byte
  counts between the process list and the sparkline; height 480 → 520.

### m10 — Top process per interface type (**removed**)

- Added `InterfaceTopMonitor.swift` / `InterfaceTopModel.swift`, spawning one
  nettop per interface type (`-t wifi` / `-t wired` / `-t awdl`) so each type
  could expose its own top processes; `InterfaceModel` gained `topSnapshots`
  and the popover a collapsible three-column "top processes" block. **Five**
  nettop subprocesses ran at that point.
- The module and its UI were later removed entirely, leaving only the
  four-bucket overview — see "Amendments".

### m11 — Same-name merge + configurable refresh

- **Same-name merge**: `ListViewModel.mergeSameNameProcesses` collapses rows that
  share a case-insensitive display name (Electron helpers,
  "Trae CN Helper.86108/.86111/.86112") into one — rates sum, pid keeps the
  smallest (stable row identity frame-to-frame), name keeps the first spelling.
  The menu-bar total is unaffected (it is computed from raw entities in
  `Network`).
- **Configurable refresh interval**: `refreshInterval` (1 / 2 / 5 s, default 2)
  plus a "Monitoring" section in Settings; changing it rebuilds and restarts
  every nettop subprocess, updating `interval` *before* the restart so the
  normalisation in `parser` always uses the current value.
- That option was later reverted to a fixed 1 s — see "Amendments".

### m12 — Multi-language

- `Feature/Localization/LocalizationManager.swift` — a runtime locale resolver.
  Follows the system language by default; `languageOverride` switches instantly
  through a per-locale `.lproj` bundle; missing keys fall back to Base English.
- Three `Localizable.strings` tables at the time (en / zh-Hans / zh-Hant), wired
  as resources in `project.yml`. Every user-visible string in the popover, the
  settings window and window titles goes through `Loc.l(_:)`. Logs stay English;
  `InterfaceCategory`'s stored values stay stable (display-only translation).
- **UX problems surfaced during verification** (recorded in
  `.trellis/spec/guides/swift-combine-swiftui-pitfalls.md`):
  - The `@Published` willSet race — a sink must use the **event's** value;
    re-reading the property silently acts on the old one (both the refresh
    interval and the sort mode were "one click late").
  - The bridged segmented Picker does not refresh its segment labels on a locale
    change (needs an `.id(locale)` rebuild) and lags one event on static windows
    (fixed with a `@State` mirror binding).
  - `Bundle.localizedString`'s "did we find it?" check needs a sentinel —
    `value != key` always fails for English, where the value *is* the key.
- **Sort UX**: the options were reordered to match the list columns
  (Name / Down / Up / Total), column headers and a per-row Total (in+out) column
  were added, and switching modes re-sorts immediately instead of waiting for
  the next nettop frame.

### m13 — History window: heatmap + interface history

- The `interface_history(ts, category, in_bps, out_bps)` table: the
  per-category socket-mode snapshot is normalised **once** at the write point
  (delta ÷ interval) and persisted per frame; retention and pruning are shared
  with the totals table.
- A standalone **history window** (lazy-cached `NSWindow`, 680×480, resizable)
  opened from a new ⤢ affordance in the popover's history section: range presets
  (Today / 7 d / 30 d) plus custom dates; interface-category checkboxes; two
  layouts from one cell set (one row per day, and a GitHub-style one column per
  day); hover shows the ↓/↑ mean rates and the ≈volume; legend and tooltip
  explain that colour encodes the hourly mean rate.
- `verify_history.swift` — 15 assertions covering normalisation, local-timezone
  bucketing, cross-midnight edges, aggregation, category filtering, empty
  windows, and the volume conversion.
- Interface data is only recorded from this milestone onward; earlier rows do
  not appear in the interface views.

### m14 — App usage tab

- The `process_usage(minute_bucket, name, name_key, in_bytes, out_bytes)` table:
  per-minute **pre-aggregation** of the process frames (raw frames would be
  ~1.3 M rows/day; minute rows are four orders of magnitude smaller).
- `ProcessUsageAggregator` accumulates normalised rates in memory and, on minute
  rollover, flushes `bytes = Σ(rate) × interval`. The grouping key is the
  lowercased process name, so a process that quits and relaunches keeps
  accumulating under one row and same-name helpers merge.
- A new **"App usage" tab** in the history window: every process's accumulated
  ↓/↑/total bytes over Today / 7 d / 30 d / custom, sortable, with a grand-total
  footer and a localised empty state; `GROUP BY name_key` keeps case variants
  from splitting.
- `verify_process_usage.swift` — 12 assertions (merge, rollover, byte
  accounting, zero-traffic skip, range filter, sort modes).
- Per-process usage is only recorded from this milestone onward.

### m15 — Quota alerts + menu-bar totals

- `Feature/Usage/UsageAggregator.swift` — the shared period-usage integrator.
  The App-usage tab, the quota monitor and the menu bar all read the same
  source, so the numbers cannot drift apart.
- **Quota alerts**: Settings gained a "Quota" section — enable toggle (which
  also requests notification authorization), period (month / week / day), limit
  in GB, and an optional custom threshold (80% and 100% are always on).
  `QuotaMonitor` fires one local notification per (period, threshold) crossing;
  the dedup keys live in UserDefaults and re-arm automatically when the period
  rolls over.
- **Menu-bar totals**: optional compact today `D` and quota-period `P` segments
  (in+out combined) appended in a single horizontal row; the status item width
  is re-measured when the segments toggle.
- `verify_quota.swift` — 14 assertions (threshold-set construction, crossing
  detection, first-observation arming, dedup, period-rollover re-arm, period
  start keys).

### m16 — Abnormal upload alerts

- The `Feature/Usage/UploadAnomalyMonitor.swift` of the time: a per-process
  rolling upload baseline (median of the last 15 non-zero frames, debounced over
  3 consecutive frames), firing only above both the multiplier and an absolute
  floor, with a 30-minute cooldown; a cold start (fewer than 5 baseline samples)
  never fired.
- Settings gained an "Upload alerts" section (master switch, sensitivity
  multiplier 2–50×, minimum rate in MB/s).
- `AppDelegate` now conforms to `UNUserNotificationCenterDelegate` and returns
  `[.banner, .list, .sound]` from `willPresent` — without it a menu-bar
  (`LSUIElement`) app, which is active the vast majority of the time, would
  never show a banner.
- `verify_upload_anomaly.swift` — 12 assertions.
- The monitor was later rebuilt as `ProcessAlertMonitor` — see "Amendments".

### m17 — Accent colour, rewritten

- `Feature/Appearance/AccentColor.swift` was rewritten from scratch as a
  self-contained subsystem: `AccentColorManager` (single source of truth),
  `View.appAccentScope(_:)` (one application point per window root), and
  `AccentHexField` (validated hex input).
- **Two sources**: *Follow system* (the macOS control accent, following live via
  the `AppleColorPreferencesChangedNotification` distributed notification — a
  System-Settings accent change repaints the app without a relaunch) and
  *Custom*. New installs default to **custom + `#00CFFF`**.
- **Global and realtime**: every window root (popover, settings, history)
  observes the manager and applies `.appAccentScope`, which both tints all
  controls (`.tint` on macOS 12+, `.accentColor` on 11) and publishes the colour
  as the `\.appAccent` environment value consumed by the hand-drawn surfaces
  (sort underlines, heatmap cells and legend, bridged toggles) — so no surface
  can drift from the others.
- **Colour validation lives in exactly one place**: hex parse/normalise
  (`#00CFFF` / `00CFFF` / `0cf`, canonical uppercase output), every colour
  conversion through sRGB, alpha always stripped (the picker is opacity-free),
  and malformed stored values falling back to `#00CFFF` at load instead of
  crashing or rendering invisible.
- Settings UI: mode picker, live swatch, native `ColorPicker`, hex field
  (red-outlined revert on bad input, canonical snap on valid input) and a Reset
  button.
- Storage keys `ft.accent.source` / `ft.accent.hex` — a clean break from the
  earlier `accentMode` / `accentRGBA` / `accentFollowSystem` keys, which are
  deleted once at launch.

### m18 — Native settings window

- The settings window became the standard macOS preferences window assembled
  from platform parts: an `NSTabViewController` (`.toolbar` style) hosting the
  tabs, crossfading between panes, the window resized to each pane's height and
  managed by `AppDelegate.showSettingsWindow()`. The macOS 13 `Settings { }`
  scene is still unavailable (the target is 11.0).
- **Every control is a platform control**: switches are real `Toggle`s;
  `EditableNumberField` keeps the native `TextField(value:formatter:)` +
  `Stepper`; the hex field uses the native bezelled text field (a red ring only
  on rejected input). `.plain`/`.borderless` chrome and hard-coded 9–15 pt fonts
  were replaced by semantic text styles and a single shared control column, so
  the panes follow the user's text-size setting.
- Destructive actions use standard `.bordered` buttons, with the native
  `NSAlert` as the confirmation step.
- **Two bugs fixed along the way, both found by running the real window**:
  - `EXC_BREAKPOINT` when selecting a pane containing a numeric field — the
    custom `NumberFormatter` subclass was copied by SwiftUI's `TextField`, and
    `copy(with:)` re-enters `init()` through Objective-C, bypassing Swift's
    stored-property initialisation. The formatter is now stock and the range
    clamp lives in the view's `onChange`.
  - The window title turned into "Untitled" when switching panes
    (`NSTabViewController` propagates the selected child view-controller's title
    by default).
- **Also fixed**: splitting the single `SettingsView` into one
  `NSHostingController` per tab removed the shared parent that carried
  `.appAccentScope`, so every settings control silently fell back to the
  *system* accent. Each pane is its own SwiftUI root, so `SettingsPane` now
  applies the scope itself.
- That tab controller was later replaced by a hand-drawn tab bar (see m22) —
  see "Amendments".

### m19 — Accent colour, all the way through

- `.tint` only reaches what SwiftUI draws. Everything AppKit draws reads
  app-wide semantic colours resolved from the **system** accent, and none of
  them can be overridden per app or per control with public API. Measured on
  this machine: `controlAccentColor` #FFC600, `keyboardFocusIndicatorColor`
  #FFFF1A, `selectedTextBackgroundColor` #8B7A3F,
  `selectedContentBackgroundColor` #D19E00.
- The remaining surfaces were therefore hand-built in
  `Feature/Appearance/AccentControls.swift` (new file):
  - **Text fields** → `AccentTextField`: a borderless `NSTextField` with the
    native focus ring suppressed, wrapped in a ring painted with the accent via
    `.accentFieldChrome(isFocused:)`, and with the text selection recoloured by
    writing the field editor's public `selectedTextAttributes`. AppKit keeps
    owning editing (field editor, IME, undo) — only the ring, bezel and
    selection colour are ours.
  - **Drop-downs** → `AccentPicker`: a button + popover list, so hover and
    selection use the accent; it picks its label colour from the accent's
    luminance so pale accents stay readable.
  - **Date / time** → `AccentDateField` (a localised month grid with accent
    selection, hover and today marker, forward navigation capped at "today")
    and `AccentTimeField` (HH:MM:SS with validation and minute stepping).
    `AccentDateField` lives in `AccentControls.swift` because all three of the
    history window's range filters reuse it too.
- **Accepted trade-off**: the hand-built controls give up NSMenu keyboard
  navigation and scrolling, the system focus ring, and the system calendar
  popup. "Follow system" mode has none of these compromises.
- **Tried and reverted: tinting the settings tab icons.** A non-template
  `NSToolbarItem.image` changes how AppKit draws the whole item (icon *and*
  label), and re-assigning an item's image makes AppKit rebuild it and drop the
  toolbar's selected item — which visibly snapped the pane back to the first
  tab.

### m20 — Settings window polish

- **Pane switches are instant**: both animations are gone — the tab
  controller's `transitionOptions` is explicitly `[]` (AppKit's default is
  `crossfade | allowUserInteraction`, so leaving it unset still crossfaded), and
  the per-pane window resize no longer animates.
- **Correction to the entry above: the accent-tinted text selection did *not*
  work at that point.** See m21. It is kept here as a record of the mistake.

### m21 — The text-selection tint actually works now

The accent-coloured text selection in the settings fields had been reported as
"still not changing" three times, twice dismissed as a verification artefact. It
was a real bug, and the previous milestone's "confirmed working" entry was
wrong.

- **Root cause**: the tint was written from `controlTextDidBeginEditing`, and
  **that delegate method is not called when the user clicks into the field**.
  Every path used to verify it until then (programmatic focus + `insertText`,
  and `makeFirstResponder` + `selectText`) either did call it or produced no
  editing session at all — so the tests kept passing while the real path painted
  the platform colour.
- **Fix**: apply the tint from the notifications the field editor posts itself —
  `NSText.didBeginEditingNotification` and
  `NSTextView.didChangeSelectionNotification` — with the ownership test
  `(editor.delegate as? NSTextField) === ourField`, and remove the observers in
  `dismantleNSView`. A highlight cannot appear without a selection change, so
  between them they cover every case.
- **Verified on the same real click path**: `attr=#00CFFF rendered=#01C0ED`
  (the app accent).
- **Lesson worth keeping**: a delegate callback is not proof that a hook runs.
  Drive the path the user actually takes before claiming "verified".

### m22 — Settings tab bar, drawn instead of native

- AppKit's preference-toolbar selection tints the selected item's **icon and
  label** with the system accent, and that styling has no override — so the tab
  bar became five SwiftUI buttons that keep `Color.primary` in every state and
  express selection purely as a neutral background highlight.
- **Three traps that went away with the tab controller** (each of which had
  already bitten once): the child view-controller title rewriting the window
  title ("Untitled"), tab item images having to be re-assigned (which silently
  dropped the toolbar's selected item and flipped the pane back to the first
  tab), and toolbar labels needing a manual refresh on a language change.
  `applyPaneSize` now runs on selection change instead of on a tab-controller
  callback.
- **Bug found while verifying it**: resizing the window synchronously from the
  `@Published` sink resized the window but left the pane unchanged — the sink
  runs *before* the property is written, so the synchronous `setFrame` re-enters
  AppKit while SwiftUI is mid-update. Deferring the resize one runloop turn
  (`DispatchQueue.main.async`) fixes it. Same family as the willSet pitfall.
- **Accepted trade-off**: the window has no native toolbar chrome, and a pane is
  rebuilt on each switch, so a pane's local `@State` resets.

## What did NOT change (deliberate)

- **`NettopRunner.swift`** — kept verbatim, including the `script -q /dev/null`
  TTY wrap and the retained stdin pipe (the "never busy-poll" fix).
- **`Utils.swift`** — the `getAppInfo` cache still backs per-row icon
  resolution.
- **Fixed 1-second sampling / delta mode / first-frame-dropped**, with rate
  normalisation still happening exactly once in `Network.parser` (dividing again
  anywhere downstream reproduces upstream issue #28: the list rendering double
  the menu bar).
- **No third-party dependencies** — only the system `SQLite3`, which is not a
  package.
- **No network requests** — the upstream's `UpdateChecker.swift` is stripped;
  its "check for updates only on click" rule is hardened here to "check for
  nothing".
- **No sandbox / no entitlements expansion** — the entitlements file is still
  the upstream's empty `<dict/>`.
- **No data leaves this machine** — no telemetry, no analytics, no remote update
  check, no remote catalog fetch. The app may read `/Applications/...` to
  extract an icon, but it does not touch any other product's binaries or private
  data structures.

## Known limitations

- The app is still **user-space nettop** — it cannot see per-connection domains
  or do the per-interface attribution a NetworkExtension product could.
  FlowTrace intentionally stays on the upstream's zero-permission architecture.
- **Notifications require user authorization, and that authorization does not
  survive a rebuild.** Both quota alerts and traffic alerts are local
  notifications; if FlowTrace is missing from (or disabled in) System Settings →
  Notifications, the system drops them silently — `add()` returns success even
  then, so the code can only tell by checking the authorization status first.
  This fork is **ad-hoc signed**, so every build is a new signing identity, and
  the notification grant is keyed to that identity. After a rebuild you may need
  to re-grant: toggling the relevant switch off and on in Settings triggers the
  system prompt again.
- **Back up the database together with its sidecar files.** In WAL mode the
  on-disk database is three files: `history.sqlite3`, `history.sqlite3-wal`
  (committed transactions not yet merged) and `history.sqlite3-shm`. The app
  never runs an explicit checkpoint, so `-wal` normally survives quit; copying
  `history.sqlite3` alone loses the most recent data. Conversely, deleting the
  sidecars loses data too. See `docs/ARCHITECTURE.md` §5.1.
- `xcodebuild test` now runs from the command line (two blockers were fixed in
  2026-09: a top-level `PRODUCT_NAME` in `project.yml` that made the app and
  test targets collide on one `FlowTrace.swiftmodule`, and assertions left
  behind by the `ListSortMode` rename). The standalone
  `scripts/verify_*.swift` harnesses that stood in for it were folded into
  `FlowTraceTests` and deleted.
  **Note that the test target is not isolated**: the test host *is* the app, so
  `applicationDidFinishLaunching` runs, which means a test run spawns real
  nettop processes and reads/writes the real
  `~/Library/Application Support/FlowTrace/history.sqlite3` and
  `~/Library/Logs/FlowTrace.log`. Judge that for yourself before running it.

## Build

```bash
brew install xcodegen
xcodegen generate
xcodebuild build -project FlowTrace.xcodeproj -scheme FlowTrace -configuration Debug
```

Or open `FlowTrace.xcodeproj` and press ⌘R. The product is `FlowTrace.app`.

There is no CI and no release script: a release is a handful of commands run by
hand, with the signing identity overridden on the command line rather than
written into `project.yml` (so a fresh clone builds with no certificate at all).
The full process is in [`AGENTS.md`](../AGENTS.md) under Releases.
