## 新内容

### 通知

- **点击导航** —— 每条系统通知都会打开对应界面：进程示警 → 历史窗口「示警日志」；
  配额阈值 → 设置 ▸ 配额；保留期提醒 → 设置 ▸ 存储。点击正文导航，动作按钮永不导航。
- **配额 100% 动作按钮** —— 100% 通知携带三个动作：**已知**（把增长基线移到当前
  用量）、**1 小时不再提醒**（内存态，重启解除）、**今天不再提醒**（持久化至当日结束）。
- **配额 100% 增长重发** —— 80% 与自定义阈值保持每周期一次；到达 100% 后，只要用量
  继续增长（每超过上次通知配额的 1%）就会再次提醒，长时间下载不会被一条横幅之后就
  沉默。

### 修复

- **进程示警同日重发** —— 去重行改为**投递前**预查。此前仅靠 `process_alert` 唯一
  索引拦不住通知本身（`INSERT OR IGNORE` 被忽略 + 60 秒评估持续成立，实测同一进程
  同方向一天连发 4 条，复现后修复）。
- **「提醒模式」启动期静默删除** —— 持久化层遗留的 init 期清理无视清理模式，每次
  启动都会删掉保留窗口外的全部数据（实测一次启动删了约 2 万行）。该清理已移除：
  删除只属于**自动清理**模式的每日检查点，「通知提醒手动清理」模式绝不删数据。
- **存储清理覆盖示警记录** —— 保留期提醒把示警记录计入逾期行数，「清除数据 /
  范围清理」现在也会删除它们。两侧同为 5 表口径；清空示警记录会同时重置同日去重状态。
- **`showPeriodInMenuBar` 持久化** —— 一次重构让该开关的订阅丢失了 `store(in:)`，
  持久化静默失效（设置项往返测试抓住）。

### popover

- **头部配额摘要** —— 头部居中显示「2.1G / 5.0G · 剩 23 天」（配额关闭时仅显示
  周期用量）。用量来源、GB 换算与周期边界与配额监视器完全同源，两边永不打架。
- **符号化表头** —— 实时↓ / 实时↑ / 今日↓ / 今日↑ / 今日∑（21 种语言统一
  Title Case；设置里的默认排序选项共用同一组 key）。
- **窗口收窄**（540 → 440）并重排列网格：进程名称列获得空间，五个数值列等宽 50pt，
  任何语言下表头缩放显示而不截断。
- **模块开关** —— 设置 ▸ 通用 ▸「popover显示」：进程列表（搜索栏 + 表头 + 行作为
  整体）、网络接口、最近 2 分钟曲线、今日峰值、今日∑、打开历史统计按钮，均可独立
  隐藏。「进程默认排序」设置也移入该组。

### 菜单栏

- **Logo 段** —— 可选的 18pt 应用图标；其余段全关时强制开启（开关禁用），菜单栏
  item 永不沦为无法辨认的空槽；其余情况自由开关（默认关）。
- **段间分隔符** —— 每对相邻段之间有 9pt 的「|」（Logo｜速率、速率｜累积，以及
  关闭速率时的 Logo｜累积）。
- **单速率垂直居中** —— 只显示一个速率时，现在与累积段一样垂直居中（隐藏行不再
  占位）。

### 设置 ▸ 通用

- 重组为带标题的分组：「菜单栏显示」（Logo / 下载↙ / 上传↗ / 今日累计D / 周期累计P）
  与「popover显示」（默认排序 + 六个模块开关），行标签缩短、子项缩进。页面加高以
  完整显示（740pt）。

### 本地化

- 21 种语言的 UI 标签与设置行 Title Case 统一（Last 2 min / Today peak /
  Interface、热力图图例句子），配额/示警设置页底部说明现在准确描述 100% 重发、
  零基线例外与周期重置机制。

## 已知限制

与 1.0.0 相同：用户态 `nettop` 无法按域名归因流量；自签名包首次启动被 Gatekeeper
拦截（见 README）；备份 `history.sqlite3` 时请连同 `-wal`/`-shm` 边车一起；
测试套件跑在应用进程内、会触碰真实数据库与偏好设置。

