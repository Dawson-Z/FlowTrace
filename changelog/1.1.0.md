# 1.1.0 — FlowTrace

> **Prebuilt builds** are attached to the Releases page as a `.dmg` and a
> `.zip`. They are signed with a self-signed certificate (bundle id
> `local.FlowTrace`, signing identity **`Dawson`**) and are **not** notarised,
> so macOS blocks the first launch until you allow it — see the README's
> [First launch](../README.md#first-launch) section. Everything works in user
> space: no System Extension, no NetworkExtension, no extra entitlements.

1.1.0 is the first feature release after the 1.0.0 baseline: notification
interactions (click navigation, quota-100% action buttons, growth-driven
re-firing), three notification-reliability fixes, a de-cluttering pass for the
popover and the menu bar, and a reorganised Settings ▸ General pane. The full
reminder & notification mechanism map now lives in
[docs/NOTIFICATIONS.md](../docs/NOTIFICATIONS.md).

## What's new

### Notifications

- **Click navigation** — every system notification opens the relevant
  surface: process alerts → History ▸ alert log; quota thresholds →
  Settings ▸ Quota; the retention reminder → Settings ▸ Storage. Body clicks
  navigate; action buttons never do.
- **Quota 100% action buttons** — the 100% notification carries three actions:
  **Acknowledge** (moves the growth baseline to the current usage),
  **Mute for 1 hour** (in-memory, lifted by a restart) and **Mute today**
  (persists for the local day).
- **Quota 100% growth re-fire** — 80% and custom thresholds stay once per
  period; at 100% the alert repeats while usage keeps growing (every extra 1%
  of the quota past the last notification), so a long download keeps being
  flagged instead of falling silent after one banner.

### Fixed

- **Process alerts re-firing within a day** — the dedup row is now checked
  *before* delivering. The `process_alert` unique index alone never stopped
  the notification (a swallowed `INSERT OR IGNORE` plus a 60-second check
  that kept evaluating true produced four alerts for the same process and
  direction in one day — measured, then fixed).
- **Silent deletion at launch in "remind me" mode** — a leftover init-time
  prune in the persistence layer ignored the cleanup mode and deleted every
  overdue row on each launch (measured: ~20k rows gone in one launch). The
  prune is removed: deletion belongs to the *automatic* mode's daily
  checkpoint only, and the manual-notification mode never deletes.
- **Storage cleanup covers the alert log** — the retention reminder counts
  alert rows as overdue, so "Clear data / Clear range" now deletes them too.
  Both sides share the same five-table scope; clearing the alert log also
  clears the same-day dedup state.
- **`showPeriodInMenuBar` persistence** — a refactor had left that toggle's
  subscription without a `store(in:)`, silently killing its persistence
  (caught by the settings round-trip test).

### Popover

- **Header quota summary** — "2.1G / 5.0G · 23 days left" centred in the
  header (bare period usage while the quota is off). Same usage source, GB
  divisor and period boundaries as the quota monitor, so the header and the
  monitor can never disagree.
- **Symbol column headers** — Live ↓ / Live ↑ / Today ↓ / Today ↑ / Today ∑
  (Title Case across all 21 languages; the settings sort options follow the
  same keys).
- **Narrower window** (540 → 440) with a rebuilt column grid: the name column
  gains the space, the five value columns are equal 50 pt, and headers scale
  down instead of truncating in any locale.
- **Module switches** — Settings ▸ General ▸ "Popover display": process list
  (search bar + headers + rows as one unit), network interfaces, the
  last-2-min sparkline, today peak, Today ∑ and the open-history button each
  hide independently. The default sort setting moved into the same group.

### Menu bar

- **Logo segment** — an optional 18 pt app mark, forced on (toggle disabled)
  while every other segment is off so the item is never an unidentifiable
  empty slot; a free choice otherwise (defaults off).
- **Segment dividers** — a 9 pt "|" between every adjacent pair of segments
  (logo|rates, rates|totals, and logo|totals while the rates are off).
- **Single-rate centring** — with only one rate visible it now centres
  vertically like the totals segments do (hidden rows no longer reserve
  height).

### Settings ▸ General

- Reorganised into captioned groups: "Menu bar display" (Logo / Download ↙ /
  Upload ↗ / Today total D / Period total P) and "Popover display" (default
  sort + the six module switches), with shortened row labels and indented
  rows. The pane grew to fit (740 pt).

### Localization

- Title-case pass across UI labels and settings rows in all 21 languages
  (Last 2 min / Today peak / Interface, the heatmap legend sentence, and the
  quota/alerts footnotes — the latter now accurately describe the 100%
  re-fire, the zero-baseline exception and the period reset).

## Known limitations

Unchanged from 1.0.0: user-space `nettop` cannot attribute traffic by domain;
self-signed builds are blocked by Gatekeeper on first launch (see the README);
back up `history.sqlite3` together with its `-wal`/`-shm` sidecars; the test
suite runs inside the app and touches the real database and preferences.

## Build

```bash
brew install xcodegen
xcodegen generate
xcodebuild build -project FlowTrace.xcodeproj -scheme FlowTrace -configuration Debug
```
